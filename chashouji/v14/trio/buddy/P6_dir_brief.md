# 精美1 · 方向版补帧说明（P6 第二轮，物理一致性）

先读 `v14/trio/buddy/P6_P7_brief.md`（整份，含末尾两节试点经验：蒙版局部重绘、只取蒙版区贴回、`scale_as`、头大小、配件每帧都在、不许做的）。本文件只写**新增的要求**，冲突时以本文件为准。

## 为什么重画

用户："路飞的手臂方向明显拐弯了，和原始动作方向不一致……所有角色不能出现原始动作方向和技能特效方向不一致、不符合真实物理动作和原理的地方。"
审查（`docs/美术打磨自检.md` 第 4 节）按物理量每个人出手：

- **投掷实物**：东西离手的速度 = 手的速度，之后只受重力、只会往下弯。引擎以后会让东西**沿"出手前一帧手位 → 出手帧手位"的方向**飞出去，再按重力落到目标。
  所以出手前一帧（`swing`）到出手帧（`release`）手的位移方向，必须等于派单给的**所需角度**（±10°），否则东西要么飞不到、要么得在空中拐弯。
- **光束 / 伸长的肢体 / 拳影 / 指尖能量球**：物理上是直线，出手帧里**手臂（肩 → 手）/ 掌 / 拳的指向**必须等于所需角度（±10°）。
- 角度记法（屏幕角）：0° = 水平向右，180° = 水平向左，**正 = 往上**，负 = 往下。哥们朝左打，所以都在 90°~270° 之间：例如 138° = 往左上 42°，−131° = 往左下 49°。
  格内坐标 y 向下，所以 θ = atan2(−(y₁ − y₀), x₁ − x₀)。

## 投掷的人要画的三帧（帧名固定）

| 帧 | 画什么 |
|---|---|
| `swing` | 出手前的引臂：持物的手拉到**出手方向的后方**——沿所需角度反方向退 90~140 输出像素（往上抛的就是手在身侧偏下、身后；平甩的是手在身后同高）。身体蓄力扭转。手型 as if holding …，手里空着 |
| `release` | **出手瞬间**：手臂沿所需角度伸出去（肩 → 手的方向 = 所需角度 ±10°），手指刚张开、东西刚离手（**手里空着，什么都不画**），身体跟着往出手方向送，头发衣角往后拖 |
| `thru` | **跟随**：手臂顺着出手方向继续走完（往上抛的人手继续往上前方扬、比 release 更高更远；平甩的人手继续扫过去），重心前送，头发衣角往前甩 |

量和交的东西（回报里逐项写数）：
1. `swing` 握点 P（输出像素，新坐标系，拳心 / 掌心 / 指捏处）；`release` 手位 R（同一个"握点"的位置）；**θ = P → R 的屏幕角**，和所需角度的差；
2. `release` 帧肩点 S、手点 R，**肩 → 手的屏幕角**和所需角度的差；
3. 两个差都 ≤ 10° 才算过。不过就改蒙版 / 提示词重生，或者微调（比如 swing 的手往后下挪：只能靠重画，不能硬贴手）。
4. `thru` 帧手的位置。

## 光束 / 拳 / 伸长肢体的人

`release` 帧（或派单写的帧名）手臂 / 掌 / 拳的指向 = 所需角度 ±10°；量肩 → 手（拳 / 掌心）的屏幕角，回报读数。另给**出口点**（光束 / 拳头 / 能量球从哪出：掌心中点 / 拳面），新坐标系。

## 画面约束（这次 combo_scan 被新帧撞出 6 对不过 + 5 人出画，新帧必须守住）

派单会给你：站位 at = [屏幕 x, 屏幕 y, s]、新 anchor、以及两条线。屏幕坐标 = at + (格内点 − anchor) × s。
- **不出画**：新帧（swing / release / thru / idle2）剪影最右 ≤ 屏幕 x 955、最左 ≥ 5；地板的人最低点 ≤ 屏幕 y 1334。
- **不往上冒**：后排（地面）的人新帧最高点不得高于派单给的屏幕 y（= 上方那排人的脚下附近），否则会挡住上方的人。
- **后排的人躯干不能往前压**：躯干（胸腹）保持在原 idle 躯干的位置附近（左右 ≤ 30 输出像素），别往左前方趴——左边是男主，躯干压过去会被男主挡掉（B8 / B9 的 thru 就是这么挂的）。
自检：build 后用 `python3 v14/trio/buddy/p6limits.py <图集名> <at_x>,<at_y>,<s> <帧,...>` 打印每帧屏幕包围盒（脚本已备好）。
