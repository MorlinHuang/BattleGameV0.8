# 档 4 出场视频制作规范

依据：2026-09-28 上线的真相女神出场视频（commit 8d77518）。后面每个角色的出场视频，**至少要达到这个水平**。

## 一、"这个水平"具体指什么（验收标准）

逐条都要做到：

1. **不是一块屏幕，是一层特效。** 视频没有矩形边框，也没有硬切。开场用 0.35 秒淡入，同时从 1.04 倍缩回 1 倍；结尾用 0.45 秒淡出。
2. **人物清晰、不透明。** 人物只在画框边缘软化；底边软化范围是其他边的 4 倍，因为特写时人物会被画框底边截断。
3. **环境和游戏融合。** 场景背景只保留 22% 的不透明度，而且越靠近画框边越淡，下面的游戏画面能透出来。
4. **光效亮在游戏上面。** 光柱、亮片、金光爆开这类亮部保留 90%。
5. **最后一秒只剩人物。** 离结尾 1.25 秒时，环境和光开始退；离结尾 0.45 秒时完全退干净。不这样做，尾帧会留下一整片过曝的金白色，看起来像一块白板。
6. **从视频里走进游戏。** 视频最后一帧的人物，和游戏立绘在同一位置、同一姿势（尾帧对齐，平均色差不超过 40，真相女神是 18）。视频淡出的同时立绘现身，再滑进悬停位开始攻击。
7. **数值不等视频。** 送礼那一刻战力就加上，视频只推迟角色本人出场。
8. **兼容性。** 只在 Chromium 内核里放视频，包括 Chrome、Edge、OBS 浏览器源和直播伴侣。Safari 不支持 VP9 透明，在 Safari 上角色照原来的方式从画外冲进来。

## 二、流程

### 1. 生成视频（即梦 Seedance）

- 规格：3:4、8 秒、1080P（没有就选 720P）、开音频、全能参考。
- 参考图：@图1 是角色立绘（抠到灰底）；@图2 是尾帧构图（人物在游戏悬停位的位置）。示例见 `truth/ref_1_角色.png`、`truth/ref_2_尾帧构图.png`、`truth/layout_示意.jpg`。
- 提示词模板见 `truth/真相女神_出场视频_提示词.md`。两个硬要求：
  - **最后 1 秒机位固定**；
  - **最后一帧是立绘的姿势**。这是"走进游戏"的前提。
- **写提示词前先做剪辑规划**（2026-09-29 用户："不是所有场景都会放进游戏，生成时就要规划好"）。对照工具规则逐样定进不进游戏：
  - 人物抠出来 100% 保留；
  - 亮部（最亮通道 > 0.62）保留 90%；
  - 其余环境只留 22%；
  - 结尾 1.25 秒开始退；
  - 底部法术潮整条保留。

  所以要进游戏的东西，要么贴着人物，要么是亮的，要么在底部那一条里；要剪掉的就让它暗。大亮块（整片光、巨大月亮、镜头眩光）会以 90% 盖在游戏上，要限定大小。
  离开人物飞出去的小东西（例如跳进云海的玉兔）要写成"化作一道流光"。样例见 `change/嫦娥_出场视频_提示词.md`「剪辑规划」。
- 背景直接用场景（卧室、光效）即可，不需要纯色幕布。工具会用 AI 抠出人物。如果要用纯色幕布，只能用品红（#FF00FF）；绿幕会把绿衣服一起抠穿。
- 即梦审核会拦截身材、服装类词，例如走光、乳沟、火辣、抹胸、超短裙、魅惑等。被拦时去掉这类描写，靠参考图来传达造型。

### 2. 过工具（一键）

打开 http://1.14.252.30:40232/ ，把 **即梦原片 + 游戏立绘**（透明底 PNG/WebP，例如 `web/assets/world/truth2_up.webp`）一起拖进去，保持默认的"自动判断"。

- 8 秒的视频大约要 6~10 分钟，主要花在 AI 逐帧抠人物上，每帧约 1 秒多。
- 出来的内容：
  - `scheme1/alpha.webm`：透明图层视频，直接进游戏；
  - "尾帧对齐"一行，例如 `vw: 834, end: { s: 0.817, x: 6, y: 8 }（色差 16.6）`；
  - 对比预览页：两个方案叠在游戏画面上同步播放。
- 有 ⚠ 警告要先处理。常见的是"立绘和视频最后一帧对不太上"：说明视频没按立绘生成，或者最后姿势变了，最好重新生成视频。

命令行版（在桌面上跑）：

```
python3 ~/vframes/vframes.py 原片.mp4 -s 立绘.webp -o 输出目录
```

### 3. 接进游戏

1. 把 `alpha.webm` 放到 `web/assets/video/<角色>_intro_alpha.webm`。
2. 在 `web/intro.js` 的 `CLIPS` 里加一条：
   ```
   <配方名>: { src: 'assets/video/<角色>_intro_alpha.webm', box: [0, 200, 960, 1280], vw: <工具给的>, end: { s, x, y } }
   ```
   `box` 是视频在画布上的位置，档 4 统一放在这里。
3. 在 `web/main.js` 的 `INTRO_OF` 里加一条 `[角色对象, '<配方名>']`。
4. 部署后用 `http://1.14.252.30:40235/index.html?autogift=drop:1:1.5` 自动送一次档 4，**录屏看**，不要看无头截图。检查三处：
   - 开场有没有矩形边；
   - 尾帧换成立绘时会不会跳；
   - 视频放完后画面是否继续刷新（`?titleclock=1` 可以看时钟）。

## 二之二、白娘子加的三件事（2026-09-29）

1. **首帧和尾帧先算镜头逻辑，再写分镜。**
   - 镜头后拉时画面中心不动：居中的近景拉到最后仍然居中，要到左上只能让人物飞过去或者镜头甩一下。
   - 白娘子定的是"前 4.5 秒正对镜头互动，4.5~6.2 秒她自己飞到左上、镜头同时后拉，6.2 秒起镜头静止"，飞行过程在画面里连续发生。
2. **视频区按尾帧对齐反推，让最后一帧的她和游戏立绘重合。**
   - 即梦尾帧里人物的大小、位置总会偏一点（白娘子是立绘的 0.745 倍）。不要让立绘现身后再滑过去、放大，而是反过来缩放、移动整个视频区：
     - k = 游戏缩放 ÷ end.s；
     - box.x = 悬停 x − (end.x + foot.x·end.s)·k；
     - box.y = 悬停 y − (end.y + foot.y·end.s)·k；
     - 宽高 = 视频宽高 × k。
   - 超出屏幕的部分由 #stage overflow:hidden 裁掉。
   - **反推出来的视频区只管最后一帧，开场段要另外居中。** 白娘子反推后视频区往左偏了 79 像素，开场正面那段她整段偏左（用户反馈"不在正中心，有点怪"）。
     做法：CLIPS 里加 `open: [x, y]`（开场时视频区左上角，让她在画布中线 480 上）和 `move: [t0, t1]`（她飞过去、镜头后拉那一段），intro.js 按播放进度把视频区从 open 平滑移到 box。画面本来就在动，这段平移看不出来。
     量法：在工具输出的 frames/ 里取正面段人物（alpha>0.85）的重心 x，占视频宽度的比例 r，则 open.x = 480 − r·box.w。
3. **视频里带着底部法术潮（海 + 虾兵蟹将）。**
   - 提示词里加 @图3（用游戏同一套贴图还原的一帧），尾帧里海的位置画进 @图2。
   - 工具加 `--fx sea`（网页上是"底部法术潮"选项）：海按颜色认出来整条保留，不随环境在结尾退掉。
     - 青蓝海水：B−G 小，这一条用来排除身上的纯蓝光晕；
     - 发灰的白沫：靠纹理认，雾是平的；
     - 虾兵蟹将：按橙红色认。
   - 同时量出尾帧海面的高度，填进 CLIPS.tide。
   - 游戏里 intro.js 放完视频调 `Tide.handoff(y)`：海直接铺满，从视频里的海面高度 1.2 秒落回原位，虾兵蟹将从水里一只只蹦出来。
4. 命令：`python3 ~/vframes/vframes.py 原片.mp4 -s 立绘.webp --fx sea -o 输出目录`，8 秒片约 5.5 分钟。

## 二之三、嫦娥加的两件事（2026-09-29）

1. **工具新增 `--fx cloud`（网页上是"月夜云海 + 玉兔金蟾（嫦娥）"）。**
   - 背景是很匀的深蓝夜空，所以反过来认：底部"不像夜空"的都算云海，只保留从左边缘连过来的那一片。
   - 腾空的玉兔、金蟾只保留它们本身，不把兔子和浪之间那段夜空也包进来。
   - 浪身左右两侧做横向羽化，避免在浪和环境之间切出一道竖直硬边。
2. **法术潮进画面的帧，盖掉再抠一次人物（`--fx` 时自动做）。**
   - 大浪和玉兔进画面后，AI 抠人物会把注意力分给它们，嫦娥在 5.9~6.5 秒被抠成了半透明。
   - 工具先把法术潮那片换成同一行背景的中位色，再重抠这些帧，抠像时间多约 1 分钟。
3. 命令：`python3 ~/vframes/vframes.py 原片.mp4 -s change1_up.webp --fx cloud -o 输出目录`，8 秒片约 8.5 分钟。
   结果：尾帧对齐色差 7.3，云海上沿在视频 y 953。
4. 近景时人物不在正中的，照白娘子的做法加 `open` / `move`（重心按工具输出 frames/ 里 alpha>0.85 的像素量）。

## 二之四、绿茶妹妹（2026-09-29）

1. **工具新增 `--fx tea`（网页上是"奶盖泡泡海 + 莲花奶茶兔（绿茶妹妹）"）。**
   - 跟嫦娥云海同一个认法（layer.py `cloud_mask(c, m, TEA)`），只换两处：
     - 夜色判据：暗粉紫，饱和度 > 0.45、亮度 < 0.34；奶泡浪亮度约 0.95、饱和度约 0.15，很好分。
     - 方向：浪从**右边**涌进来，参数 `side: +1`，只要从右边缘连过来的那一片。
   - 命令：`python3 ~/vframes/vframes.py 原片.mp4 -s sister1_up.webp --fx tea -o 输出目录`，8 秒片约 8 分钟。
   - 结果：尾帧对齐色差 13.2，浪上沿在视频 y 980。
2. **开场元素要对准游戏里的对应物。**
   - 片子开场那部手机，按反推的视频区落在画布 (451, 898)，正压在游戏里男女主抢的那部手机 (454, 898) 上，读成"她从那部手机里钻出来"。
   - 所以没加 `open`：近景她只偏中线 21 像素，挪了反而把手机挪开。
   - 做法：参考图 @图4 按 `FX.phoneX/Y` 画手机位置（`video/sister/make_refs.py`）。
3. **参考图按游戏真实坐标用脚本画**（`make_refs.py`：站位、手机、法术潮三层和小兵都从游戏配置取），改站位后重跑即可。
   - 注意：档 4 贴图四边的外发光是截断的，边上 alpha 还有 26~32。放到深色参考图上会露出矩形框，脚本里要把四边羽化掉。

## 三、方案选择：直接放视频 vs 帧动画

对比数据来自真相女神这条视频，8 秒，均衡档：

| | 方案一：透明视频 | 方案二：帧动画图集 |
|---|---|---|
| 文件 | 3.7 MB | 22 MB（6 张图集） |
| 运行时内存 | 一个视频解码器 | 解码后 330 MB |
| 帧率 | 原片 24 帧/秒 | 15 帧/秒 |
| 声音 | 自带 | 要另外对时 |

结论：**场景类出场视频一律用方案一。** 方案二只适合纯色幕布拍的小尺寸人物动作，比如只占画面一角的短动作。那种情况每帧只存人物外框，品红测试片解码后才 39 MB。

## 四、踩过的坑（别再踩）

- **不要在游戏里用 WebGL 实时合成**（上下拼接的"画面 + 遮罩"视频）。桌面容器的 Chrome 没有 GPU，上下文一建就丢，整块画面发白。无头截图里却是好的，会被它骗。所以透明效果一律离线烤进 VP9 alpha webm。
- **放过的 `<video>` 收起时用 `visibility:hidden`，不要用 `display:none`**。否则桌面 Chrome 整页合成会停住：JS 还在跑，画面却冻住了。
- **即梦片子的帧率元数据不能信。** 时间戳按 1/60 秒取整，元数据报 60，实际是 24 帧/秒。工具已改为按真实时间戳判断帧率。
- **AI 抠像的并行度按 cgroup 配额算**（桌面是 8 核），每个进程 1 个线程。如果按 `os.cpu_count()`（报的是宿主机 72 核）去开线程，会互相抢核，慢 2~3 倍。进程开到 24 个会撑爆 16G 内存。
- **模型** `~/isnet-anime.onnx`（176 MB）和 onnxruntime 1.30 只装在桌面上。桌面重建后要重新装：先在本机 `pip download onnxruntime --python-version 3.12 --only-binary=:all:`，scp 到桌面，再 `--no-index` 安装。
