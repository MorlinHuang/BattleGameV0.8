# 查手机 · 拉扯动作改生视频 · 总方案（2026-10-05）

## 〇、先说游戏里动作是怎么被驱动的（方案的前提）

- 胜负由礼物实时决定：两人在长卷上往左还是往右、多快、什么时候停、什么时候反拽，**每一秒都可能变**。
- 输方的狼狈程度分四档：**僵持 → 跪 → 扑倒 → 趴**（女赢、男赢各一套，共 7 个状态）。
  规则：一档一档走，不跳档；每档至少停 0.6 秒才换；输方反拽成功时**倒着一档一档爬回来**。
- 一局里这种"倒下—爬起"会来回发生很多次，不是从头到尾放一遍。

所以不管视频怎么做，游戏都不能"从头放到尾"，只能把视频拆成一格一格的画面，按当时的状态挑着播。

## 一、一条长视频 还是 拆成多条？—— 建议拆，但要用"锚点姿势"保证一致

### 一条长视频的问题

1. **提示词控制不住阶段**：即梦一条最长 10~15 秒。档 4 出场视频的经验是：白娘子那条写了 3 个动作节点（近景→2.5 秒嘘手势→5 秒聚水球），基本按顺序出来了，但每个节点落在第几秒只能大致控制。
   把"僵持 → 女生跪 → 扑倒 → 趴着被拖 → 反拽爬起 → 男生跪 → …"六七个节点写进一条，这么多节点我们还没试过。按目前的经验，大概率会被压缩、跳过或乱序，每段多长也定不住。
2. **游戏里用不起来**：一局里倒下、爬起要反复很多次，方向随时变。长视频只能"按进度往前/往后拖着放"。
   但倒放时摔倒变成"从地上弹起来"、扬起的灰往地里缩，一看就是倒带。
3. **一处不满意就整条重生**：哪怕只有"扑倒"那 2 秒腿画坏了，也得把整条 15 秒重新抽卡。

**长视频的价值**：可以生成一条当"动作预演"，看看模型理解的整体节奏和表演，取它好的动作写进分段提示词。但不直接进游戏。

### 拆成多条：游戏动画的标准做法是"状态循环 + 状态间过渡"

```
            女赢一侧                              男赢一侧
  aL趴 ⇄ aF扑倒 ⇄ aK跪  ⇄   n0 僵持   ⇄  bK跪 ⇄ bF扑倒 ⇄ bL趴
   ↻        ↻        ↻           ↻             ↻        ↻        ↻
```

- **7 段循环**（↻）：每个状态一段，在这个状态下被拖着走、或僵持时的来回较劲。
- **6 段"倒下"过渡**（→）：僵持→跪、跪→扑倒、扑倒→趴，两侧各 3 段。
- **6 段"爬起"过渡**（←）：趴→扑倒、扑倒→跪、跪→僵持，两侧各 3 段。
  不能拿"倒下"倒着放。加了扬灰、衣摆被蹭上去这些细节之后，倒放一眼就穿帮。爬起应该是另一套动作：撑地、拽着手机借力起身、顺手把衣摆拽下来。
- 合计 **19 段**，每段 3~5 秒，每段生成 4 条挑 1 条。

### 拆开后一致性怎么保证：每一段的首尾帧都钉在同一张"锚点姿势图"上

7 个状态各有一张定稿图（现在线上就是这 7 张：n0、aK、aF、aL、bK、bF、bL）。所有视频都用即梦的**首尾帧模式**：

| 段 | 首帧 | 尾帧 |
|---|---|---|
| aK 循环 | aK 图 | aK 图 |
| 僵持→跪（女赢） | n0 图 | aK 图 |
| 跪→僵持（男生爬起） | aK 图 | n0 图 |
| …… | | |

两段视频接在一起的那一格是**同一张图**，所以段与段之间不会跳。模型只能在中间自由发挥，开头和结尾被钉死。
这跟现在步态"每格都从原图出发"是同一个思路，只是从"一格一张"变成了"一段一条连续视频"。

中间帧的小偏差（人物大一点小一点、位置挪一点）由我逐帧按手机和躯干对齐，再拉回到锚点图的坐标里。

### 拆开之后游戏里可能出的漏洞，以及怎么堵

| 漏洞 | 原因 | 处理 |
|---|---|---|
| ① 画面跟不上局势 | 现在每档停 0.6 秒、过渡帧只有 0.3~0.43 秒；视频过渡一段 1.5~3 秒，礼物刷得快时会比距离条慢一拍 | 过渡一开始就播完，不中途打断；局势变化快时最多加速到 2 倍；播完马上按最新局势决定下一段。距离条、数字是真实结果，动画允许慢 1 秒左右 |
| ② 脚底打滑 | 循环段里人走一步的距离和游戏里平移的距离对不上，看起来像在溜冰 | 从视频里量出脚、膝盖贴地的那几帧，算出一圈走多远；游戏按"拖了多远"推进画面（现在步态就是这么做的） |
| ③ 地上的痕迹、灰跟着人跑 | 视频里镜头跟着人走，画在视频里的拖痕会粘在屏幕上，不会留在地板上 | **拖痕、灰尘由游戏画在地板上**（拖痕现在已有），视频里不要；我从视频里量出每帧膝盖、手、鞋贴地的位置，灰从那里扬起来。这样换房间时灰的颜色也能跟着地板变 |
| ④ 衣着变化前后矛盾 | 衣摆在"扑倒"时被带上去，到了"趴"的循环里又回到原处 | 衣着的变化要**画进锚点图**：bF、bL 的锚点图本身就是露腰的样子，"爬起"那段里把它拽下来。不能留下"一段里有、下一段没了"的状态 |
| ⑤ 帮手瞄不准 | 闺蜜、哥们、礼物要打在脸、短裤、身体轮廓上，现在每张姿势图都量了这些位置 | 每一帧都重新量一遍（脚本现成） |
| ⑥ 首屏加载变慢 | 帧数从几十张涨到几百张 | 循环段按每秒 12~15 格抽，过渡段按需加载，首屏只带僵持；目标是首屏仍在 4 秒内 |
| ⑦ 平台审核 | 露腰、趴地这类画面，即梦生成时、抖音直播里都可能被审核 | 提示词里写死"不暴露"；尺度由你最终判定 |

## 二、细节设计（让拉扯更真实、更生动）

总原则：**跟人走的东西进视频，留在地上的东西由游戏画。**

- 进视频：身体、衣服、头发、表情、拖鞋，以及它们的连带动作（甩头发、衣角翻飞、拖鞋半掉）。
- 由游戏画：地板上的拖痕、扬起的灰、受击闪光、汗珠和怒气符号。

### 1. 僵持 n0（循环）
- 两人都在发抖较劲：手臂绷直微颤，脚掌在地上一点点打滑又踩稳，重心你来我往地前后晃（对应现在 ±1% 的晃动）。
- 女生：咬牙、鼓腮，头发随身体前后晃；兔子拖鞋往前滑一小截又蹬回来。
- 男生：皱眉咬牙，敞开的睡衣下摆随身体晃动；黑猫拖鞋鞋底打滑。
- 游戏：拖鞋打滑的位置出极淡的蹭痕。

### 2. 跪（K）
- 倒下过渡：后脚一滑，膝盖一软先单膝跪地、再双膝跪下，上身被拽得往前一冲，手始终没松手机。整个过程是"腿软跪下"，不是摔。
- 循环：膝盖贴地被拖着往前滑，小腿和拖鞋在身后拖，脚尖时不时蹬地想停住；每被拽一下，上身往前一冲再往后挣。
- 女生（bK）：短裤花边被膝盖带着微微卷起，头发滑到一侧肩前，表情从生气变成慌。
- 男生（aK）：睡衣一侧滑到肩膀边，下摆拖在身后飘，表情是不服气的咬牙。
- 游戏：两道膝盖拖痕（已有），起步时膝盖处扬一小团灰。

### 3. 扑倒（F）
- 倒下过渡：**轻微摔倒，不激烈**。身体被拽得往前一扑，先用一只手肘撑了一下又赶紧去抓手机，胸口贴地前上身有个小缓冲，没有弹跳、没有翻滚。
- 女生（bF）：
  - **双臂被拽得往前伸直，吊带睡衣下摆被带上去，露出一截腰和肚脐**（10-05 用户定 C2：放弃断吊带——游戏里太小看不清）。睡衣仍完整遮住胸口。这一状态延续到趴，爬起时她顺手把下摆拽下来。
  - 发卡上的小红花滑落、挂在发梢，几缕头发搭在脸上，脸颊和膝盖一点灰，委屈又不服。
  - 一只兔子拖鞋半掉，挂在脚尖上晃。
- 男生（aF）：
  - 敞开的睡衣被地面蹭得往上卷到背上，一侧衣领滑下肩膀。
  - 短裤不动，保持原样，避免和上一轮"短裤变长"的问题混在一起。
  - 一只黑猫拖鞋半掉、挂在脚尖。头发更乱，脸上一道浅浅的灰印。
- 游戏：扑地那一下在胸口、手肘处扬一圈灰，之后膝盖和鞋尖拖出两道痕。

### 4. 趴着被拖（L）
- 循环：整个人贴地被拖着滑，双臂伸直死抓手机，腿在后面无力地拖着，偶尔蹬两下想翻身。头发、衣服都被地面往后带。
- 女生（bL）：下摆被地面蹭得更上去，露出侧腰（与扑倒一致），短裤花边沾灰，头发铺在身后，小花挂在发梢。表情是闭眼咬牙死撑，偶尔抬头瞪一下。
- 男生（aL）：睡衣整片翻到背上，露出侧腰；半掉的拖鞋随拖动一甩一甩。表情是绝望地喊。
- 游戏：身体压过的地方拖出宽一点的灰痕，速度快时身前扬起一点细灰。

### 5. 爬起（反向过渡）
- 趴→扑倒：手肘撑地、借着手机的拉力把上身撑起。
- 扑倒→跪：一条腿收回来跪住，女生**顺手把睡衣下摆拽下来**，男生把衣领耸回肩上、拖鞋蹬回脚上。
- 跪→僵持：踩地站起，猛地一拽，重新回到对峙。
- 这一套动作就是反拽成功的"翻身感"，比把倒下倒着放有表现力得多。

### 不做的东西（避免穿帮或审核问题）
- 不掉拖鞋（掉了之后几个状态很难再穿回去，只做"半掉挂在脚尖"）；不撕破衣服；不露内衣；不受伤、不流血；没有剧烈翻滚和弹跳。

## 三、制作顺序

1. **先重画锚点图**：在 bF、bL、aF、aL 四张锚点图里加上衣着状态（吊带滑落、睡衣卷起、拖鞋半掉）。用生图改图，你确认后再出视频。
2. **先做女赢一侧的一整条链**：n0 循环 + aK/aF/aL 三段循环 + 3 段倒下 + 3 段爬起，共 10 段。我接进游戏，挂在网址参数后面，你在网页里看完整的倒下→拖→爬起。
3. 一整条链效果认可后，再做男赢一侧剩下 9 段（僵持循环两侧共用）。
4. 之前发的 aK 试点（跪着被拖的循环）就是第 2 步里的一段。你已经生成了的话直接交来，我先拿它把抽帧、抠像、对齐这条流程跑通。
