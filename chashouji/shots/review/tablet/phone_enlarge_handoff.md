# 手机稍微放大（用户 2026-09-27 定）

用户原话：「就用当前这个手机 稍微放大点就行 聊天信息还是以气泡表现 不要修改」
- 手机样式不变，不换平板。
- **追加（同日）**：屏幕亮着，显示成某个聊天软件的界面，但不显示具体聊天记录（屏太小）。原话：「手机屏幕可以亮着 然后软件是某聊天软件，但屏幕太小 不用具体显示聊天记录」
- 气泡（bubble.js）一行都不改。

## 已定 ×1.3（用户 2026-09-27 拍板）
- 手机从约 51×25 放大到约 66×33，面积是原来的 1.7 倍。
- 对照图：`phone_enlarge.png`（n0 / aF / bL 三个姿势，各 ×1.0 / ×1.3 / ×1.5）；`phone_enlarge_fullsize.png` 是 n0 原大。
- ×1.5 的问题：机身两头从拳头后面伸出一大截，在 bL 那种斜拿的姿势里尤其明显，看起来像两人抓着一块板的中段。×1.3 两头刚好藏在拳头后面，读起来仍然是"攥着手机两头"。

## 做法：只改构建，不重新生图
所有贴图，包括 11 张关键姿势和 42 张步态帧，都经过 `v14/build.py:295` 的 `build_pose`，它在第 301 行调 `find_phone` 找到手机。在这里加一步就能覆盖全部贴图：
1. 用 `find_phone` 的中心，取那块近黑连通块，外扩 2px 把描边带上，抠出来。
2. 以中心为原点放大 1.3 倍，贴回原位。
3. 把原图里机身周围的手，也就是肤色加描边的像素，再盖回最上面，保证手在手机前面。
   示意脚本是本对话里的 `enlarge()`；肤色判定用 r>150、r>g+10、g>b−5，外扩 2px。
4. 这一步要放在 `cutout` 之后、`edge_extend` 和缩放之前，在原图分辨率下做，边缘更干净。

## 不用改的
- 手机中心点不变，所以 `meta.phone`、弹幕瞄准线、气泡起点都不变。
- `PHONE_GAP = 70`（main.js:1240）比放大后机身的半宽 33 大得多，不用改。
- `find_phone` 的面积上限是 0.03·h·w，放大 1.7 倍后仍在范围内；长宽比也不变。

## 落地后复核（审查角色）
- 53 张贴图都要看 `v14/preview/phone_check.jpg`：手有没有盖对，有没有漏出旧的小机身轮廓。
- 步态连播时手机不能一闪一闪：每格放大后的大小和位置要一致。
- 气泡、弹幕打手机的命中位置跟改之前一样。

## 追加：亮屏（聊天软件界面，无文字）
示意图：`phone_lit.png`，三个姿势，每个都比原样、×1.3 黑屏、×1.3 亮屏；`phone_lit_fullsize.png` 是 n0 原大。
- 界面由几部分组成：绿色顶栏（带白色圆形头像和一条白色名字条）、几条左白右绿交替的空白气泡、灰色底部输入栏。**不写任何字，也不画任何真实 App 的 logo**，只让人读出"在聊天"。
- 屏幕沿机身主方向贴，斜着拿的 aF / bL 也跟着斜。四周留 2~3px 的黑色边框；屏幕宽 = 机身长 × 0.86，高 = 机身宽 × 0.72~0.8。示意里 n0 上沿的黑边偏厚，正式做建议取 0.8。
- 顺序很重要：先用黑色机身找手机（find_phone），再放大，最后贴屏幕，再把手盖回去。屏幕亮了以后 `find_phone` 就找不到它了，所以只能在原图上找一次。每张图都是从未处理的原图重新构建，这一条天然满足。
- 界面是同一张固定贴图（不随机），所以 53 张帧里屏幕内容完全一致，连播不会闪。
- 屏幕上的绿色要和 main.js 的聊天气泡、真相喷雾的青柠色区分开：示意用的是 (58,190,120)，偏蓝绿，跟青柠 (156,238,96) 不撞色。

### 亮屏修正（用户反馈"屏幕并没有发亮"）
上一版屏幕只涂成浅灰白色，在明亮底图上读成"一块白东西"，读不出亮着（原因同 chashouji-fx「发光靠色相」）。新版示意 `phone_glow.png`（左上一版、右新版）、`phone_glow_fullsize.png`：
- 屏幕底色改成冷色渐变，中心 (250,255,255) 到边缘 (150,215,255)；顶栏更饱和 (20,200,110)，气泡不加描边。
- **光晕**：画在机身后面的一圈柔光，颜色 (80,200,255)，把机身轮廓外扩约 4px、再高斯模糊 9px，透明度 0.75。这是读成"亮着"的主要来源。
- **照到手**：离屏幕 14px 以内的拳头染一点冷光。示意里强度 0.45 偏重，整只拳头都发蓝、像戴了手套，正式做取 0.2~0.25、范围 8px，只染靠屏幕那一侧的指节。
- 光晕和染色都烘进贴图，不走运行时的 lighter；每一帧参数相同，连播不会闪。

## 已落地（2026-09-27，总管）
`v14/build.py` 的 `enlarge_phone` / `light_phone` / `screen_tex`，参数表 `SCREEN` / `GLOW` / `HAND_LIT` / `OLD_PAD`。与本文档的出入：
- 照到手按离**露出来的**屏幕多远算（range 10、a 0.3、颜色 190,235,255）；按离整块机身算，压在机身上的整只拳头都算贴着屏幕，发灰。
- 盖回手：旧机身凸包外扩 9px 那一圈里只盖肤色（外扩 3px 带描边），圈外不透明像素全盖。只按肤色挑手会漏指缝阴影；按灰/暗认旧机身会漏斜拿时带色偏的下沿，屏上一排点。
- 屏幕 4 倍大画、4 倍大转再缩回，原尺寸直接转斜拿的边成一排锯齿点。

## 用户反馈（2026-09-27）：聊天界面应该是竖的
原话：「聊天软件的方向在屏幕里应该是竖的，现在是横的」
- 现状 `v14/build.py:229` 的 `screen_tex(w, h)` 按横拿画：顶栏在长边、气泡横着排，读成"在横屏里用聊天软件"，真实手机不会这样。
- 改法：按竖屏画一张 `h×w` 的界面，也就是宽 < 高：顶栏在上，气泡左白右绿**上下**排 4~5 条，底部是输入栏；画完转 90° 再交给 `light_phone`（build.py:268）。
- 转的方向：顶栏落在女主那一侧（左）。手机被横着拽，屏幕内容没有随着转成横屏，读起来就是"竖屏聊天界面被横着拿"。
- 两头会被拳头盖掉：顶栏在最左边，大半压在她的拳头下，露出来的主要是中段的气泡。所以气泡要占满中段，顶栏可以窄一点，取屏长的 0.12。
- 冷色渐变、光晕、照到手这些都不变。
- 示意（只看方向）：`screen_orient.png`。

## 竖屏界面已落地（2026-09-27，总管）
`screen_tex(w, h)` 按竖屏画（顶栏 0.12、输入栏 0.1、六条气泡左白右绿上下排），`light_phone` 里逆时针转 90° 再跟机身斜，顶栏在女生那头。
