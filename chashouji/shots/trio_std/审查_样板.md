**必改 1：走路循环的腿是错的。** 图集 walk1、walk3 两个接地帧是**同一条腿在前**：两帧都是近侧腿（粗黑条那条，画在上层）迈在前面，远侧腿在后（`审2_B5_walk1-2-3腿部_walk1与walk3同一条腿在前.jpg`）。seq 是 walk1 → walk2 → walk3 → walk2，腿永远不换边，读起来是同一条腿反复往前蹭。另外**双节棍换手**：walk1 棍在远侧手，walk2、walk3 在近侧手（黑条袖子那只）（`审2_B5_walk四帧_双节棍换手.jpg`）。每走一圈，棍在两只手之间跳一次，在 `改_B5_enter` 格 2→3、格 10→11 能看到。
- 改法：重生条 2（模板 C 走路条）。提示词写死这几点：frame 1 近侧腿在前接地，frame 3 远侧腿在前接地（两帧腿要左右对调），frame 2 和 4 是两腿交错的过渡帧（一张近侧腿在抬，一张远侧腿在抬），双节棍四帧都在近侧手。walk 改成 4 张不同的帧（walk1~walk4），seq 写 `['walk1','walk2','walk3','walk4']`。
- 验收：四帧逐一看，1、3 前后腿对调；棍始终在同一只手。

**必改 2（引擎，影响所有 walk 的人）：脚在地上滑。** `改_B5_enter` 格 7、格 8 都是 walk2（间隔 110ms），着地那只鞋的左沿从屏幕 x 910 挪到 877，**同一帧里着地的脚滑了 33 px**。原因在 trio.js place() 的 walk：身体每一帧（60fps）都在连续平移，走路帧却 7fps 才换一张，所以一张帧停留的 0.14 秒里，踩在地上的脚跟着身体一起滑。速度也对不上：进场全程 390px（画外 423×0.85+30），用 1.3 秒，身体平均 300 px/s（起步 375、到位 225）；按图集接地帧两脚距离约 190 格内像素 ×0.85 = 161 px、两帧一步、每秒 7 帧算，脚步应走 7 × 161 / 2 ≈ 564 px/s。
- 改法（引擎负责人）：walk 的位移**跟帧走**。只在换帧那一刻前进，同一帧停留时位置不动，dx 取这一帧开始时刻的值；bob 也一样。每换一帧前进 `enter.stride / 2 × s`，其中 `stride` 是新增字段，写接地帧两脚距离（格内像素）。进场帧数 = 距离 ÷ 每帧步长，自动取整；最后一步落到 at 位置上。这样踩在地上的脚在一帧之内是钉死的。
- 验收：`ammoms=40 ammoskip=0` 拍进场，同一帧名连续几格里，着地那只鞋的屏幕 x 差 ≤ 2 px。

**必改 3（引擎，影响所有后排地面的出手）：出手路径横穿自己主角的脸。** B5 站在男生身后，出手点 `from [80,104]` 换算到屏幕约 (646, 840)，正好在男生头部这个高度。棍影从这里往左飞向女生，一路从男生脸上过。`改_B5_atk` 格 10、11 的棍影和速度线压在男生嘴和下巴上（`审2_B5_atk格8-12_棍影压男生脸.jpg`）。同一个问题在 `测_ride_whip` 格 11~12 更明显：抽打的链子画成一条黑带，横过男生眼睛，并且停留整段 phases（`审2_测_ride_whip格11-12_链子横过男生眼睛.jpg`）。`测_appear_punch` 格 9~10 伸出去的手臂管子也横过男生脸。原因：后排的人站在自己主角身后，打的是对面主角的脸，而出手的东西、特效都画在主角之上（drawOver），所以出手点只要和头一样高，一定会穿过自己主角的脸。B5~B10、G4~G10 这 14 人都会中。

### 5.4 drift.py 的 robust=0.08 会不会放过真漂移

**不会放过 ≥ 1 px 的真漂移，但在真胶片上会自己加进约 ±1 px 的噪声。所以它只能做辅助，不能当唯一读数。**

- **合成测试**（`审2_robust合成测试.py`，输出在 `审2_robust合成测试.txt`）：
  - 做法：`改_B5_enter` 格 1（B5 还没进画）当底图，把 idle 帧按已知位移贴上去；再把 `改_B5_idle` 格 9 里男生挡在 B5 前面的像素盖回去（前脚框被挡 25%）。
  - 结果：注入 dx 0.5 / 1 / 1.5 / 2 / 3 / 4 / 6、dy 2 / 4、dx −3、(2, −2)。robust 以格 1 为零点，量回 0.76 / 0.97 / 1.24 / 1.74 / 2.68 / 3.71 / 5.71、1.82 / 3.89、−3.40、(1.79, −2.13)，**每项误差 ≤ 0.4 px，而且偏小**。
  - 结论：真漂移 2.3 px 时，可能读成 1.9 px 被放过。
- **真胶片的噪声**：`改_B5_idle` 格 8→9 都是 idle，robust 前脚读数 dx 从 −0.86 跳到 +1.21，一格跳了 2.07 px。同一格用不被挡的后脚、不截来量，只跳了 0.99 px，而且跳的格不同、方向相反。说明前脚被挡住时，截断后的误差面有两个谷，robust 在两个谷之间来回跳。报告里 B5 的 "1.47 px" 就是这个噪声的上沿，不是真漂移。
- **规范已改（8.3）**：
  - 后排的人主读数用**不被挡的那只脚 + 不截**；
  - robust 只在两只脚都被挡时用，门槛收到 **≤ 1.6 px**（2 − 0.4 误差）；
  - 1.6~2.4 之间的，要看 onion 图人工判；
  - robust 读数里前后两格跳动超过 1.5 px 的，那一格的读数作废。

### 5.5 新写法：能不能做出"精致动画"，哪些会让人变死板

先说总的判断：引擎里 12 种进场，**路线都是整张图的变换**（平移、转、缩放、淡入）。人会不会死，全看 enter.seq 里有没有换姿态。所以"会不会死板"要看两件事：这种写法里美术有没有地方换帧；规范有没有逼他们换。

- **根因**（trio.js `over()`）：
