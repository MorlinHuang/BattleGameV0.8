### 判据成不成立：**三人之间成立，但有 4 个漏洞，其中 2 个让"全过"不成立**

判据是：后面的人逐帧被挡 ≤ 8%，头框被挡 0，认人点（躯干 + 挂件 + hold 道具）被挡 0。在"三个槽位之间"这个范围内，做法是对的：按 depth 定前后、前面那人取全部在场帧的并集、头框按模板逐帧重找、外扩 4 px 比。三对实拍（见下）也和矩阵读数对得上。问题在范围和定义上：

1. **主角不在遮挡物里（最大的漏洞）**。combo_scan.py 里没有男生 / 女生（grep 不到 girl / boy / 主角），而主角就站在后排和地板中间，是屏幕上最大的遮挡物。实测：

   矩阵对这些全读"过"。**改法**：把两个主角加进遮挡物，按在场时身体 / 长发扫过的范围取并集（拉锯时他们前后晃，取胶片上一段拉锯各帧的并集；主角是帧序列 + 骨骼，可以直接在页面里画一遍取 alpha）；判据照旧，和同组合计 ≤ 15%、头框 0、认人点 0。

### B5 的结论（重点 1）：鞋尖距差 31 是读感问题，**放过**，后排样板签字

- **7.2 那条"鞋尖距差 ≤ 10"是为了什么**：引擎一帧前进一个固定步长，两步长短不一样的话，着地那只脚换帧时会滑。现在美术量的四次换帧，着地鞋 |Δx| ≤ 1，**滑步这个目的已经达到了**。
- **没满足 ≤ 10 的代价**：脚钉住了，差出来的长度就只能摊到身子上，变成一步长一步短。我在图集上量了头的位置，按 stride 209.5 推每一帧头往前挪多少：88.4 / 113.2 / 95.5 / 121.9 格内 px，左右两步 201.6 和 217.4，差 **7.5%**。对照已签的 B10（同样是一张底图出的四帧）：每帧 92.6 / 68.8 / 64.8 / 92.9，两步 161.4 / 157.6，差 2.4%；按帧看起伏（极差 / 均值）B5 是 32%，B10 是 35%，一样。
- **读感**：7.5% 的步长差，要连着看好几圈才看得出有点跛。可是 B5 进场一共只走 dist 434.7 格内 px，也就是 4~5 帧、不到一圈，而且前两步还在画外（`审9_B5_走路进场_…` 格 7~10）。玩家看不出来。
- **结论**：这一条不挡签字。规范 7.2 的"≤ 10"改成验收写法：**换帧钉脚 ≤ 6 px 为硬线；左右两步前进量差 ≤ 10% 为读感线**。已在 `审查_样板.md` 第七节补签字行。
