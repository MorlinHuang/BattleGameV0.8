# 3D 转盘素材：怎么选 lean 档、怎么量体积感（给后面做物品的人）

原来这里记的两条待办都已解决，现在这份是方法，不是待办。

## 1. 转轴：只用 `lean=`，别再用 `axis=`

`common.py` 的 `render_turntable(..., lean=)` 是转轴从视线轴往屏幕横轴偏多少度。
两条极端各自的毛病（`axis='X'` 翻过去就是背面、`axis='Y'` 是贴纸打旋根本没转）common.py
的 docstring 已经写清楚了，这里只补一条上过当的：

**`axis='Y'` 的产物在验收里是能过的，在用户眼里是废的。** 八件里七件这么渲过，逐帧都认得出、
每帧都是 3/4 角，但连起来看就是一张图在平面里打旋，用户一句"不够 3D 也没有三渲二的体积感"。
教训：**可读性够用就行（2/3 的帧），体积感才是要争的那一项。**

## 2. 怎么量"到底是不是真在三维里转"——用旋转不变量

肉眼最容易被骗：贴纸打旋看上去也在"动"。用两个**屏幕内旋转不会改变**的量，变了就是真转了：

- **可见面积**（alpha>8 的像素数）
- **剪影主轴细长比** `sqrt(λ1/λ2)`（二阶矩特征值之比开根）

平面内怎么转，这两个数都不变；只有物体在三维里转、发生透视压缩，它们才会动。实测对照：

| | 旧（`axis='Y'/'Z'`，贴纸） | 新（`lean=`） |
|---|---|---|
| milktea | 面积波动 8%，细长比波动 **2%** | lean 68：面积波动 23%，细长比 1.11~1.69（**51%**） |
| ringbox | 面积波动 30%，细长比波动 18% | lean 40：面积最小/最大 47%，细长比 1.01~1.83（**81%**） |
| photo | 面积波动 9%，细长比波动 **9%** | lean 40：面积最小/最大 54%，细长比 1.20~2.57（**114%**） |
| hairpin | lean=0 实测：面积 99.7%，细长比 **0.8%** | lean 50：面积最小/最大 78%，细长比 1.76~2.72（**54%**） |
| seed | lean=0 实测：面积 99.6%，细长比 **0.8%** | lean 50：面积最小/最大 59%，细长比 1.84~3.20（**74%**） |
| pillow | lean=0 实测：面积 99.8%，细长比 **0.1%** | lean 90：面积最小/最大 42%，细长比 1.05~2.80（**167%**） |
| gamepad | lean=0 实测：面积 99.7%，细长比 **0.3%** | lean 35：面积最小/最大 76%，细长比 1.36~2.12（**56%**） |

细长比波动个位数 = 36 帧的剪影能互相旋转重合 = 贴纸。脚本见本次验收用的
`/tmp/vol.py`（十几行，PIL + numpy，随手可重写）。

## 3. 怎么量"还认不认得出"——数识别点的像素

别靠感觉数帧。每件挑一个**识别点的专属颜色**，逐帧统计它的像素数，低于中位数 12% 的帧算废：

- milktea → 吸管的粉（`r-g>32 且 b-g>8 且 r>150`）
- ringbox → 戒环的金（`r>160 且 r-b>55 且 g-b>28`）
- photo → 人影的蓝（`b-r>16 且 b>120`）

于是"选哪一档 lean"变成一道能算的题：**往大调 lean，直到废帧数开始涨得比细长比快就停。**
三件实测（12 帧快测，废帧数）：

- milktea 45/60/68/75 → 0/2/2/2，细长比波动 19%/30%/44%/57% → **取 68**（60 往上废帧不再增加，体积感还在涨）
- ringbox 32/40/46/55 → 0/1/2/3，细长比波动 66%/68%/64%/66% → **取 40**（再大只丢金环，细长比不涨了）
- photo 25/35/40/45 → 0/0/1/4，细长比波动 27%/70%/105%/139% → **取 40**（45 一下废 4/12，整整三分之一只剩一根木条）

`tilt`/`roll` 在 lean 模式下是**固定姿态偏置**，不跟着转轴滚；三件统一 0.26/0.20，跟手柄那几件一致。

## 4. 单格边长跟着并集走，绝不上采样

`pack_atlas.py --cell` 大于并集就是在放大像素。现状（渲染边长 / 并集 / 单格）：
milktea 336 / 264 / **264**（1:1），ringbox 416 / 406 / **336**（下采样），photo 416 / 348 / **336**（下采样）。
hairpin 146 / 96 / **96**（1:1），seed 144 / 96 / **96**（1:1），pillow 224 / 160 / **160**（1:1），gamepad 249 / 161 / **160**（下采样）。
换档位会改并集（斜轴扫的圆更大），**每次重渲都要重量一遍再定 cell**。

## 5. 按形状选 lean 的两条规律（轻礼物四件量出来的）

第 3 节那套"往大调到废帧涨得比细长比快就停"是通用办法，但**起点该从哪儿试，看形状就能先猜出来**，
能省掉一半快测：

- **两面都有内容的扁平件，lean 要往大给，甚至直接给 90。** 抱枕缝线兔耳两面对称，翻过去还是抱枕。
  实测 50/65/75/90 四档的废帧（12 帧里读不出的）是 **5 / 3 / 4 / 2** —— 越大越好，反直觉。
  原因：扁平件绕任何斜轴都必然扫过一次侧沿，lean 决定的只是**在侧沿上磨蹭多久**。正面偏角随
  `cos(angle) = cos²a + sin²a·cosθ` 走，a 小的时候这条曲线在 90° 附近很平（连着好几帧都是侧沿），
  a=90 时退化成 `angle = θ`，一穿而过只废 1~2 帧。
  **前提是两面对称**；手柄内容只在正面，lean 大了等于白丢一半帧，只能给 35。

- **细长件塌不塌，看长轴跟转轴的屏幕投影夹角，不是看 lean。** 转轴的屏幕投影总是横向的，于是：
  长轴**竖着**（发卡、瓜子）→ 永远垂直于转轴 → 投影最短剩 `cos(lean)`，lean=50 还有 64%，很安全；
  长轴**横着**（手柄）→ 夹角只有 lean → 长轴会扫到正对镜头，lean=35 时最短只剩 **34%**，剪影收成一团。
  救法不是压 lean（那会一起把体积感压掉），是**加 roll 把物体在画面内斜过来**：roll 绕视线轴，
  直接打开长轴和转轴的夹角。手柄 roll 从 0.20 加到 0.90（51.6°），最短投影从 34% 抬到 56%，
  最窄那两帧从"一团"变成"看得见摇杆和按键"，lean 还是 35 没动。
  顺带：`tilt` 会把竖着的长轴往视线方向拽，**细长件的 tilt 只能给小值**——发卡光是 tilt=0.25
  就把最短投影从 64% 拉到 51%。
