# 3D 转盘素材：怎么选 lean 档、怎么量体积感（给后面做物品的人）

原来这里记的两条待办都已解决，现在这份是方法，不是待办。

## 1. 转轴：只用 `lean=`，别再用 `axis=`

`common.py` 的 `render_turntable(..., lean=)` 是转轴从视线轴往屏幕横轴偏多少度。
两条极端各自的毛病（`axis='X'` 翻过去就是背面、`axis='Y'` 是贴纸打旋根本没转）common.py
的 docstring 已经写清楚了，这里只补一条上过当的：

**`axis='Y'` 的产物在验收里是能过的，在用户眼里是废的。** 八件里七件这么渲过，逐帧都认得出、
每帧都是 3/4 角，但连起来看就是一张图在平面里打旋，用户一句"不够 3D 也没有三渲二的体积感"。
教训：**可读性够用就行（2/3 的帧），体积感才是要争的那一项。**

## 2. 怎么量"到底是不是真在三维里转"——用旋转不变量

肉眼最容易被骗：贴纸打旋看上去也在"动"。用两个**屏幕内旋转不会改变**的量，变了就是真转了：

- **可见面积**（alpha>8 的像素数）
- **剪影主轴细长比** `sqrt(λ1/λ2)`（二阶矩特征值之比开根）

平面内怎么转，这两个数都不变；只有物体在三维里转、发生透视压缩，它们才会动。实测对照：

| | 旧（`axis='Y'/'Z'`，贴纸） | 新（`lean=`） |
|---|---|---|
| milktea | 面积波动 8%，细长比波动 **2%** | lean 68：面积波动 23%，细长比 1.11~1.69（**51%**） |
| ringbox | 面积波动 30%，细长比波动 18% | lean 40：面积最小/最大 47%，细长比 1.01~1.83（**81%**） |
| photo | 面积波动 9%，细长比波动 **9%** | lean 40：面积最小/最大 54%，细长比 1.20~2.57（**114%**） |
| hairpin | lean=0 实测：面积 99.7%，细长比 **0.8%** | lean 50：面积最小/最大 78%，细长比 1.76~2.72（**54%**） |
| seed | lean=0 实测：面积 99.6%，细长比 **0.8%** | lean 50：面积最小/最大 59%，细长比 1.84~3.20（**74%**） |
| pillow | lean=0 实测：面积 99.8%，细长比 **0.1%** | lean 90：面积最小/最大 42%，细长比 1.05~2.80（**167%**） |
| gamepad | lean=0 实测：面积 99.7%，细长比 **0.3%** | lean 35：面积最小/最大 76%，细长比 1.36~2.12（**56%**） |

细长比波动个位数 = 36 帧的剪影能互相旋转重合 = 贴纸。脚本见本次验收用的
`/tmp/vol.py`（十几行，PIL + numpy，随手可重写）。

## 3. 怎么量"还认不认得出"——数识别点的像素

别靠感觉数帧。每件挑一个**识别点的专属颜色**，逐帧统计它的像素数，低于中位数 12% 的帧算废：

- milktea → 吸管的粉（`r-g>32 且 b-g>8 且 r>150`）
- ringbox → 戒环的金（`r>160 且 r-b>55 且 g-b>28`）
- photo → 人影的蓝（`b-r>16 且 b>120`）

于是"选哪一档 lean"变成一道能算的题：**往大调 lean，直到废帧数开始涨得比细长比快就停。**
三件实测（12 帧快测，废帧数）：

- milktea 45/60/68/75 → 0/2/2/2，细长比波动 19%/30%/44%/57% → **取 68**（60 往上废帧不再增加，体积感还在涨）
- ringbox 32/40/46/55 → 0/1/2/3，细长比波动 66%/68%/64%/66% → **取 40**（再大只丢金环，细长比不涨了）
- photo 25/35/40/45 → 0/0/1/4，细长比波动 27%/70%/105%/139% → **取 40**（45 一下废 4/12，整整三分之一只剩一根木条）

`tilt`/`roll` 在 lean 模式下是**固定姿态偏置**，不跟着转轴滚；三件统一 0.26/0.20，跟手柄那几件一致。

## 4. 单格边长跟着并集走，绝不上采样

`pack_atlas.py --cell` 大于并集就是在放大像素。现状（渲染边长 / 并集 / 单格）：
milktea 336 / 264 / **264**（1:1），ringbox 416 / 406 / **336**（下采样），photo 416 / 348 / **336**（下采样）。
hairpin 160 / 138 / **138**（1:1），seed 160 / 130 / **130**（1:1），pillow 224 / 160 / **160**（1:1），gamepad 249 / 161 / **160**（下采样）。
换档位会改并集（斜轴扫的圆更大），**每次重渲都要重量一遍再定 cell**。

## 5. 按形状选 lean 的两条规律（轻礼物四件量出来的）

第 3 节那套"往大调到废帧涨得比细长比快就停"是通用办法，但**起点该从哪儿试，看形状就能先猜出来**，
能省掉一半快测：

- **两面都有内容的扁平件，lean 要往大给，甚至直接给 90。** 抱枕缝线兔耳两面对称，翻过去还是抱枕。
  实测 50/65/75/90 四档的废帧（12 帧里读不出的）是 **5 / 3 / 4 / 2** —— 越大越好，反直觉。
  原因：扁平件绕任何斜轴都必然扫过一次侧沿，lean 决定的只是**在侧沿上磨蹭多久**。正面偏角随
  `cos(angle) = cos²a + sin²a·cosθ` 走，a 小的时候这条曲线在 90° 附近很平（连着好几帧都是侧沿），
  a=90 时退化成 `angle = θ`，一穿而过只废 1~2 帧。
  **前提是两面对称**；手柄内容只在正面，lean 大了等于白丢一半帧，只能给 35。

- **细长件塌不塌，看长轴跟转轴的屏幕投影夹角，不是看 lean。** 转轴的屏幕投影总是横向的，于是：
  长轴**竖着**（发卡、瓜子）→ 永远垂直于转轴 → 投影最短剩 `cos(lean)`，lean=50 还有 64%，很安全；
  长轴**横着**（手柄）→ 夹角只有 lean → 长轴会扫到正对镜头，lean=35 时最短只剩 **34%**，剪影收成一团。
  救法不是压 lean（那会一起把体积感压掉），是**加 roll 把物体在画面内斜过来**：roll 绕视线轴，
  直接打开长轴和转轴的夹角。手柄 roll 从 0.20 加到 0.90（51.6°），最短投影从 34% 抬到 56%，
  最窄那两帧从"一团"变成"看得见摇杆和按键"，lean 还是 35 没动。
  顺带：`tilt` 会把竖着的长轴往视线方向拽，**细长件的 tilt 只能给小值**——发卡光是 tilt=0.25
  就把最短投影从 64% 拉到 51%。

## 6. 真正决定体积感的是内部结构密度，转轴和转速都调不动它

换 lean、调转速，用户还是说手柄"不够 3D"。量出来才看明白：把外轮廓剥掉之后，
**剪影里面是空的**。`tools/3d/measure_volume.py` 的第 0 把尺子就是量这个。

补结构只有一条路：**真几何**。材质分区（缝线、兔耳、脊线、色块）不产生任何描边，
在这把尺子下等于不存在 —— 它只管"认得出"，不管"体积感"。手柄和抱枕这一轮补的是：

| | 补了什么 | 密度 | 屏幕结构量 |
|---|---|---|---|
| gamepad | 双摇杆 + 十字键 + ABXY 底盘 + 两个肩键 + 背壳边框（内缩 0.15） | 14% → 56% | 17 → 76 |
| pillow | 枕面板两圈（轮廓的 75.5% / 60%）+ 四块拼布，**两面都做** | 4% → 30% | 7 → 56 |

配套的三条：

- **贴在面上的凸块要带直裙边扎进主体**，别贴着放 —— 两个面在接触圈附近几乎相切，
  Freestyle 会长出一圈乱跳的小黑睫毛（摇杆当年栽过一次）。
- **顶面要比底面外扩一点点（悬挑）。** 垂直壁在正视时法向正好垂直于视线，前后朝向
  符号不定，描边会一帧有一帧无地闪。
- **顶面按同心环细分，不要从中心拉扇形。** 扇形三角又长又尖，面心落不准，
  想在凸块顶面用材质分区画小色点（ABXY 的四个键、抱枕的兔耳）根本画不出来。

## 7. 排得下几个零件是一道能算的题

屏幕描边宽度 W（实测，不是标称）、零件间距 g，`g < 2W` 两条描边就连成一条粗黑带。
手柄正面横向只有 96 屏幕px、竖向 34px，W≈8px → 一排最多四个零件，且分不出上下两层。
按这个算式砍掉的：ABXY 的四个分离小凸起（每个 8px，边距不够）、十字键和 ABXY 各自的
浅色底盘（底盘边和键边只隔 1.4px）。砍掉之后改用**材质分区**表达 —— 分区不产生描边，
不占间隙预算，颜色照样把"四个键"说清楚。

**色点别做太小**：手柄 ABXY 第一版色点半径 0.05 单位（屏幕 4.2px），渲出来红色像素
中位只有 13 个、还有两帧是 0，识别色废帧判据直接挂掉。放大到 0.072 才数得出来。

## 8. ~~渲染边长要按"内部结构线宽"反推~~ —— 根因已修，这条作废

这一节原先记的是：`k` 正比于 res，而 Freestyle 把 `render.line_thickness` 和
`linestyle.thickness` 相乘、两处都带 k，所以线宽按 **k²** 走，res 两头都是坑
（抱枕 res=150 内部线细到密度读成 0%，手柄 res=249 外轮廓 8.7px 糊死），
只能夹在中间试出 210/265。

**那是 bug，不是规律，现在修掉了。** `tools/3d/probe_ink.py` 渲正方块标定出
`线宽 ≈ 0.85 × render × linestyle − 0.65`（2.6×5.2 与 5.2×2.6 结果完全相同，
对称性就是乘法的证据）；`common.py` 现在把 `render.line_thickness` 固定成
中性的 1.0，倍率只乘进 linestyle 一边。

**于是描边宽度与 res 彻底无关**——不管 res 多少，屏幕上都是 `OUTLINE_W` = 2.8px。
res 回归它唯一的职责：决定图集分辨率，按老规矩 `res = 单格边长 / 并集占比` 反推即可，
不必再为了平衡线宽去迁就它。210/265 这两个数是 bug 时期的产物，不要再沿用。

同期查清的另一件事：原先那"两档描边"里 `select_border` 对封闭网格一条线都不产生，
`select_external_contour` 在正交相机下同样不出线——外轮廓和自遮挡线在这套用法下
**分不开**，现在只留一档 `select_silhouette`。所以"调内部线宽没反应"不是错觉。

整条管线连同这些坑已经抽成 `danmu-3d-sprite` skill，出新物品先读它。

## 9. 「墨占实心」是屏幕尺寸的函数，不是建模水平的函数

描边是**屏幕上的绝对像素**（OUTLINE_W=2.8），而物品画多大是引擎定的（`GIFT[x].r`）。
于是同一个模型画得越小，描边占掉的比例越大。拿戒指盒做对照——**只改 `screen_r`，模型一个字没动**：

| screen_r | 屏幕 px | 墨占实心 |
|---|---|---|
| 64（它真实的档） | 199 | 30% |
| 48 | 152 | 36% |
| 32 | 102 | 50% |
| 21（＝瓜子那一档） | 68 | **68%** |

**所以"墨占要落在 29~45%"这条只对 190px 以上的单投档成立。** 齐射档（瓜子 56px、
发卡 62px）物理上到不了，拿大件的数字去卡小件，只会把小件逼成一个没有任何内部结构的光板。

小件该怎么卡：**跟同尺寸的参照比**。把一件公认做得好的（戒指盒）按目标 `screen_r` 重渲一遍，
拿它的墨占当天花板。本轮实测 68px 档天花板 68%，瓜子 62% / 发卡 63%，都在天花板以下。

判"糊没糊"真正靠得住的还是第 3 节那把**识别色**尺子（专属颜色逐帧像素数，低于中位 12% 算废），
它跟尺寸无关。两件都是 0/36 废帧。


## 10. 深色物体的暗面会被当成描边——密度和墨占都会虚高

`measure_volume.py` 判墨的办法是「离 `INK`(58,44,38) 的 RGB 距离 < 46」。
**深色主体的暗面会落进这个球里**：手柄机身 `#3d4450` 渲出来的暗面是 (47,59,75)，
离墨色只有 **41** —— 整片暗面被算成描边。

一眼就能诊断出来的办法：**把阈值从 46 收到 20 再量一遍，两个数差多少就是虚高多少**。

| | 阈值 46 | 阈值 20 | 结论 |
|---|---|---|---|
| 手柄（机身 #3d4450） | 59% | 34% | 25 个点是假的 |
| 抱枕（粉白） | 32.8% | 31.2% | 干净 |

上一轮手柄报的「密度 55%、结构量 76」有一多半是这个假阳性，**不是真结构**。
提亮到 `#4c5566` 之后暗面离墨色 67，同一套结构老实量出来是 26%。

**这不只是量得准不准的问题**：描边跟主体暗面一个色，观众那边同样是看不见的——
描边白画了。所以修法不是改尺子，是**把主体提亮到暗面离墨色 ≥60**。
新做深色物品，先拿一帧量一下暗面到 `INK` 的距离，再开始堆结构。

## 11. 屏幕结构量有硬天花板，先算够不够再定指标

`屏幕结构量 = 内部结构密度 × 屏幕px² / 100`，三个量各有上限：

1. **密度受排布规矩限**：内部按 `g ≥ 2W` 填满条纹，极限是 `W/(W+2W) = 33%`。
   实测最高的花束 35%（它的花瓣本来就有轻微相接）。
2. **密度还受墨占限**：墨占实心 ≈ 密度 + 8~15 个点（差值是外轮廓占的，
   件越细长差值越大：花束 +8、相框 +9、抱枕 +9、手柄 +15）。
   要墨占 ≤45%，手柄的密度就封顶在 **30%**。
3. **屏幕px 是引擎定的**，`px = 2 × GIFT[x].r × scale`，建模侧动不了。

于是给一件东西定"结构量要到多少"之前，先算它**到底可能到多少**：

    结构量上限 = min(33%, 45% − 墨占差值) × (2·r·scale)² / 100

八件里手柄最吃亏：`r=52` 是最小的（花束 76 / 奶茶 72 / 相框 68 / 戒指盒 64），
px 只有 111，而 px 是进平方的。算出来手柄的上限是 **36**——
要它到 60，只能把 `GIFT.gamepad.r` 从 52 提到 67 左右（main.js），
在 r=52 下「结构量 ≥60」和「墨占 ≤45%」互斥，不是建模能补的。

## 12. 凸起的壁必须是斜的，直壁一条描边都不出

摇杆第一版是根直筒（同一半径从裙边拉到顶面）。**正视时直壁的法向正好垂直于
视线，前后朝向符号不定，Freestyle 判不出这是不是轮廓，一条线都不画**——
渲出来是一坨没有边的浅蓝，对内部结构密度的贡献是 0。

`slab()` 的 `taper`（顶面比底面外扩一点，侧壁微微悬挑）就是为这件事加的，
但旋转体那边漏了。凡是"从面上支出来的东西"，剖面都要带一点外张：
摇杆现在是底盘 0.94r → 收腰 0.78r → 帽檐 1.00r，帽檐和底盘各出一条线。
