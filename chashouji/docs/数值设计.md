# 《查手机》弹幕礼物与数值设计

> 数值锚点取自两份平台标杆的真实文档：《螂人杀》（兵力消耗）、《龙王斗女帝》（推线）。
> 两者用的是**同一套抖音平台礼物**，所以相对价值可以直接继承，不必自创。

---

## 零、核心结论

**这是三层，不是一层。**（2026-09-21 起，此前胜负层是手机位置，见 §八）

| 层 | 螂人杀 | 查手机 | 谁改变它 |
|---|---|---|---|
| 战力层 | 兵力 | **拉力 fA / fB** | 礼物直接注入；双方互相消耗 |
| 胜负层 | 血量 | **血量 hpA / hpB（各 100）** | **只有拉力差**才扣它，归零者负 |
| 显示层 | 战线位置 | **对抗线 p（0~100）** | 拉力差的**当前读数**，不积分 |

礼物**不直接扣血，也不直接推手机**。礼物注入拉力，双方拉力互相抵消：
- **差值决定手机在哪** —— `p = 50 + 50 × 差 / 1000`，对面追上来手机自己走回去；
- **差值每秒扣对方的血** —— 差 > X 时，每 M 点差每秒扣 Z 滴；
- 双方拉力相等时手机停在正中、谁也不掉血，刷得再凶都一样。这正是"拔河"该有的
  样子，也是这个玩法最长的那一段。

对照需求里给的例子：双方拉力都 1000 → 手机停在 50% 不动，双方每秒各扣 20 点拉力；
两边都归零时手机**仍在 50%**；若一方 1000 另一方 0 → 差 1000 → 每秒扣对方 5% 的血。
**这个例子就是 §2.5 里 Z = 5 的出处**（螂人杀公开文档没写掉血速率）。

**礼物分几档**要拆成两问：**数值 7 档**（跟平台礼物走）、**表现 5 档**（由美术成本和可分辨性定），
两者用映射表连接。

官方攻略里的两条，正是双属性结构的直接推论：
- "兵力保持敌方二分之一或三分之一，**兵少的一方消耗慢**"
- "100w 兵对 30w 兵的消耗速度**高于** 100w 兵对三次 10w 兵，所以不要刷 10 次 1 块，
  而是直接刷 10 块的兵，更省票"

## 二、双属性模型

### 2.1 为什么当前代码是错的

```js
// main.js 现状
S.p = clamp(S.p + p.from * p.g.gain, 0, 100);   // gain = 0.8 / 7 / 18
```

礼物直接瞬移进度条，只有一个属性。三个后果：

1. **没有对冲。** 两边同时刷是"你推我 18、我推你 18"交替瞬移，演不出僵持。
2. **先刷的人白刷。** 进度被后续操作覆盖，理性策略是憋到最后再刷。
3. **6 个被子从 0 推到 100。** 封闭赌注下一个人就能决定结果。

### 2.2 正确的结构

```js
// —— 战力层：礼物注入，双方互相消耗 ——
FA += gift.push;                       // 查岗党拉力
FB += gift.push;                       // 灭迹党拉力

const lo = Math.min(FA, FB);
const burn = C * lo;                   // 对冲：双方等量消耗，由拉力少的一方定速
FA -= (burn + D_LOSS * FA) * dt;
FB -= (burn + D_LOSS * FB) * dt;

const diff = FA - FB;

// —— 显示层：手机位置 = 拉力差的当前读数（不积分，0.45 秒趋近）——
const want = 50 + 50 * clamp(diff / LINE_FULL, -1, 1);
S.p += (want - S.p) * approach(dt, LINE_RATE);

// —— 胜负层：差过了死区 X，每 M 点差每秒扣对方 Z 滴血 ——
if (Math.abs(diff) > X) {
  const z = Math.min(HP_MAX, Math.abs(diff) / M * Z) * guard(hp);
  if (diff > 0) hpB -= z * dt; else hpA -= z * dt;
}
```

`C` 是对冲系数，`D_LOSS` 是自然流失（势头会过去），`X / M / Z` 见 §2.5。

**手机位置为什么不再积分**：积分量被推过去就回不来，于是"刷了礼物"和"一直被压着"
读起来是同一件事；而拔河里绳子本来就能拉回来。拆开之后两件事各归各位 —— 手机位置
回答"此刻谁力气大"（送礼物一秒内就看得见），血量回答"这么耗下去谁先倒"。

**这个结构有一个很干净的性质**，它决定了整局的节奏：

```
稳态时  diff = Δ注入率 / D_LOSS
```

> 推导：设 FA>FB，稳态下注入=消耗。
> `injA = C·FB + D_LOSS·FA`，`injB = C·FB + D_LOSS·FB`，相减得 `injA - injB = D_LOSS·diff`。

也就是说 —— **手机移动的速度只取决于"两边刷礼物的速度差"，与刷了多少总量无关。**

这正是我们要的：双方都在猛刷 → 差值小 → 手机几乎不动，但画面极其激烈；
一方停手 → 差值拉开 → 手机被拽走。**礼物的价值取决于对方刷不刷**，这是营收引擎。

### 2.3 三件从结构里长出来的好事（不是补丁）

1. **礼物的价值不会凭空消失。** 上一版的指数衰减模型里，你刷的推力 8 秒后归零，白刷。
   这里你的火力只会被**对方的火力**对冲掉——对方不刷，你的火力就一直压着。
2. **防守是有效策略。** 刷火力可以把差值拉回 0 止损，不只是进攻。劣势方有事可做，
   而上一版模型里劣势方只能干瞪眼。螂人杀官方攻略的"防守打法"正是这个。
3. **天然橡皮筋。** 因为对冲速度由**火力少的一方**定速，劣势方的火力流失慢、补火力效率高。
   这是从机制里长出来的，比硬加一个"劣势方 ×1.5"的补丁优雅得多。

第 3 条还解释了螂人杀那句"不要刷 10 次 1 块，直接刷 10 块"：分散刷会让差值一直挂在高位，
每一秒都在挨打；一次刷够能把差值瞬间压平。**省的不是钱，是挨打的时间。**

### 2.4 濒死保护：火力就是护盾

照搬螂人杀"最后 100 滴血，兵力 >3000 优先掉兵"：

```js
// 血量进入最后 10 滴时，拉力越足减伤越多（按比例，不碰存量，原因见 §六.1）
if (hp < SHIELD_AT) z *= 1 - Math.min(SHIELD_MAX, mine / (his + 1) * 1.5);
```

效果：**濒死时刷礼物直接保命，而且看得见**——火力条在替你挡。
这比抽象的"伤害减免"强得多，因为它把"该刷了"这件事明明白白摆在观众面前。

再加龙王的**反击时刻**：第一次有人掉到最后 8 滴血时触发，120 秒内劣势方**注入量 ×2**，
全局只触发一次。（注意是放大注入，不是放大伤害——要与双属性结构一致。）

### 2.5 数值标定

| 参数 | 取值 | 怎么来的 |
|---|---|---|
| `C`（对冲系数） | 0.165 | 决定拉力存量水平与对撞密度，不影响掉血速度 |
| `D_LOSS`（自然流失） | 0.040 | 时间常数 25 秒，决定差值量级 |
| `X`（掉血死区） | **30 拉力** | 螂人杀「最后 100 滴血，兵力 >3000 才优先掉兵」的 3000 兵 ÷ 100 |
| `M`（掉血分母） | **1000 拉力** | = 螂人杀 10 万兵（`push` = 兵数 ÷ 100，同一把尺） |
| `Z`（掉血速率） | **5 滴/秒/千拉力差** | ⚠️ 螂人杀文档**没写**，取自需求例子「差 1000 每秒扣 5%」 |
| `HP_MAX` | 10 滴/秒 | 掉血上限：再碾压也要 10 秒，否则观众看不清就结束了 |
| `LINE_FULL` | 1000 拉力差 | 对抗线满幅：差到这么多手机被拽到底，与 `M` 共用一把尺 |
| `LINE_RATE` | 2.2（0.45 秒） | 对抗线趋近速率。直接赋值会让手机"咯噔"闪一下 |
| `push` | **螂人杀兵数 ÷ 100** | 继承已验证的相对价值 |

**⚠️ X / M / Z 的出处要说清楚**：螂人杀的公开文档里只有兵数表、绝杀线（兵力差 500w）
和血量保护（最后 1000 / 100 滴血、兵力 3000），**没有"每多少兵每秒扣几个点"这条**。
所以 X 和 M 是从文档里的兵力刻度换算来的，Z 是需求里给过的那个例子。
`Z = 5` 的后果见 §八 —— 一局 1~2 分钟就结束，要 12 分钟得取 `Z = 0.27`。

**这三个数是同一根时间轴上的刻度，改一个必须三个一起按同样倍数改。**
2026-09-21 从 `0.05 / 0.012 / 0.08` 整体 ×3.3 到现值。原因是截图量出来的一条：
送一件「爱的爆炸③」出去，**血条 20 秒纹丝不动，60 秒才跳 1 个百分点**。礼物的
效果一点没少，只是摊在八十秒里，在直播间等同于没发生。

三个一起乘，平衡分文不动 —— 稳态净差 ÷3.3 而 `DPS` ×3.3 正好抵消：

| 校验项 | 旧 (0.05/.012/.08) | 新 (0.165/.040/.27) |
|---|---|---|
| 稳态手机速度（注入 23:11.5） | 0.0746 点/秒 | 0.0775 点/秒 |
| 均势时手机位置（注入 40:40） | 50.00 | 50.00 |
| 300 秒累计弹幕 | 1005 发 | 1106 发 |
| 单件礼物总推进 | 不变 | 不变 |

唯一变的是**单次注入多久消化完**（83 → 25 秒），顺带弹幕在礼物落地后集中打出
而不是慢慢漏。副作用据实记：**碾压局会快 17~24%**（注入 60:10 时 228s → 173s），
根因是旧数值前八十秒火力还在爬坡；均势局与接近均势的局（23:23、23:18）不变。

⚠️ **"兑现速度"和"总推动力度"是两件事，别混。** 这次只改了前者。后者（单件
爆炸③ 总共只推 1.5 个百分点＝手机 4.6px）是原始设计——礼物买的是持续火力、
靠累计，不是一次性伤害。要放大它只调 `DPS`（均势时手机仍然不动，改的是净差
换算成进度的倍率），但那会改变玩法手感并缩短局长，`MATCH` 与绝杀阈值得跟着
重配，**未拍板前不要动**。

**三个校验**：

| 场景 | Δ注入 | 稳态差值 | 手机速度 | 从中点到底 |
|---|---|---|---|---|
| 优势方每 10 秒一个爱的爆炸，劣势方一半 | 11.5 | 288 | 0.078 点/秒 | **11 分钟** ✅ |
| 一方猛刷，对方完全不还手 | 23 | 575 | 0.155 点/秒 | **5.5 分钟** ✅ |
| 双方都不刷 | 0 | 0 | 0 | **永不结束** ✅ |

最后一行正是用户例子里的"双方火力归零时手机仍停在 50%"——手机只对**差值**有反应。

### 2.6 礼物数值表

一件礼物打出去（对方完全不还手），它值两样东西：

**一、马上把手机拽过去多少** —— `p = 50 + 50 × push / LINE_FULL`，随拉力流失走回来
**二、一共扣掉几滴血** —— `(push - X) / M × Z / D_LOSS`，即 `(push - 30) × Z / 40`

| 平台礼物 | 螂人杀兵数 | `push` | 对抗线峰值 | 手机位移 | 扣血 `Z=5` | 扣血 `Z=0.27` | 表现档 |
|---|---|---|---|---|---|---|---|
| 点赞 | 1 | 0.01 | 50.0 | 0px | 0 | 0 | 0 |
| 666 | 6 | 0.06 | 50.0 | 0px | 0 | 0 | 0 |
| 仙女棒 | 100 | 1 | 50.0 | 0.1px | 0 | 0 | 1 |
| 技能宝箱 | 1000 | 10 | 50.5 | 1.4px | 0 | 0 | 1 |
| 魔法镜 | 2000 | 20 | 50.9 | 2.8px | **0** | **0** | 2 |
| 能量电池 | 11000 | 110 | 55.1 | 15px | 10.0 | 0.54 | 2 |
| 爱的爆炸 | 23000 | 230 | 60.7 | 32px | 25.0 | 1.35 | 3 |
| 派对话筒 | 36000 | 360 | 66.7 | 50px | 41.2 | 2.23 | 3 |
| 神秘空投 | 60000 | 600 | 77.8 | 84px | 71.2 | 3.85 | 4 |

（对抗线峰值与扣血都是 node 实算并与网页真实代码对过，见 §八）

⚠️ **档 0/1 和魔法镜②一滴血都不掉** —— 它们的注入量压根过不了死区 `X = 30`。
这是死区的设计意图（双方咬在一起时不该有人掉血），但要知道它的边界：**单件魔法镜
在静场下确实是零伤害**，只有多件累加把差值顶过 30 才开始扣。免费档买的本来就是
参与感不是战力，可魔法镜②是付费档的第一件 —— 要不要把 `X` 压到 15 让它有感，
是个可以拍的板（`?x=15` 现场试）。

点赞与空投之比 1:60000，与螂人杀一致。1000 人各点 20 次 = 200 拉力，能把手机拽走
10 个百分点、扣 21 滴血——**人多能顶一个爱的爆炸③，但顶不过持续砸大礼物**。

### 2.7 胜负条件三件套

| | 判定 |
|---|---|
| **主** | **血量归零**（`hpA` 或 `hpB` ≤ 0），归零的一方负 |
| **副** | 倒计时结束（12 分钟），血多的一方胜；血差 < 3 滴判平 |
| **绝杀** | 血量差 ≥ 35 滴持续 60 秒 → 30 秒绝杀倒计时，结束时仍血多则直接胜 |

**"推到端点停留 3 秒"这条已经删掉。** 手机位置现在是拉力差的瞬时读数，一件神秘空投④
自己就能把它顶到 78、两件顶到底 —— 再拿它判胜负，等于让最贵的那件礼物一键结束比赛。
新模型里端点不值钱，**压住对方的那段时间**才值钱：血是一秒一秒扣出来的，擦一下端点
什么也拿不到。这条比旧的"停留 3 秒"更硬，因为它不需要一个时长补丁去挡住擦碰。

## 三、火力怎么让观众看见

双属性最大的风险是**第二个属性看不见**。观众刷了礼物，手机没动，如果屏幕上没有任何交代，
他会认为这游戏是假的。所以火力必须有直接的可视化，而且要能解释"为什么手机没动"。

**火力 = 屏幕上的弹幕密度，对冲 = 弹幕在半空对撞。**

| 数值 | 画面 |
|---|---|
| 对冲部分 `C × min(FA,FB)` | 双方弹幕在**中线相撞爆开**，谁也没打着谁 |
| 净差 `diff` | 多出来的那些**穿过中线**，砸在对方身上，手机被拽动 |
| 火力存量 | HUD 上的火力条 / 角色脚边堆着的物品 |

于是：
- **僵持**＝满屏对撞、手机纹丝不动 —— 画面最激烈的时候恰恰是手机不动的时候
- **碾压**＝一边的东西长驱直入砸到对面脸上
- **"我刷了怎么没动"** 有了可见的答案：**你的东西被对面在半空撞掉了**

这是弹幕玩法里最需要解释的一件事，而这套表现不需要新技术——现有弹幕系统加一个中线相遇判定。

**顺带解决一个现存问题**：现在只有点礼物按钮才发射弹幕，平时屏幕是空的。改成火力驱动
自动发射后，只要有火力就一直在扔东西，对抗画面才是连续的。

⚠️ **常规火力弹幕一律不顿帧**，只有礼物注入的那一下（档 3/4）才顿帧。
否则会退回"世界被冻住 65% 的帧"那个老问题。规则是：**背景火力不打断，礼物事件才打断。**

## 四、礼物分几档

> 本节只定「分几档、每档数值多少」。**每档具体扔什么东西、分档依据怎么量化**，
> 见同目录《礼物设计.md》——那里有八个可测维度的总表、三条选型硬判据和四套物品方案。

### 4.1 数值 7 档，表现 5 档

档数的上限不是价格带定的，是**能不能做出可分辨的表现**定的。现有证据：当前 3 档里，
连珠与单投一眼能分；单投与重击靠物品体积（r=56 vs 78）加顿帧（70 vs 110ms）——
**已经是可分辨的临界**，中间再插一档做出来也白做。

扩档只能靠质变。五档各有一个前一档没有的东西：

| 表现档 | 质变点 | 平台礼物 | 查岗党 / 灭迹党 |
|---|---|---|---|
| **0** 氛围 | —— | 点赞、666 | 只加火力，**不飞实体** |
| **1** 连珠 | **有实体飞过** | 仙女棒、技能宝箱 | 发卡×8 / 瓜子×8 |
| **2** 单投 | **屏幕震动 + 顿帧** | 魔法镜、能量电池 | 抱枕 / 手柄 |
| **3** 重击 | **命中染色 + 角色被推开** | 爱的爆炸、派对话筒 | 被子 / 外卖箱 |
| **4** 处决 | **独占屏幕，打断一切** | 神秘空投 | 待定 |

**只有档 4 要新做美术**，0~3 全部复用现有资产。

### 4.2 表现力差多少（可测量）

| 表现档 | 顿帧 | 震动 | 粒子 | 染色 | 独占 |
|---|---|---|---|---|---|
| 0 氛围 | 0 | 0 | 3~5 | — | 否 |
| 1 连珠 | **0** | 2px | 8×12 | — | 否 |
| 2 单投 | 70ms | 6px | 60 | 0.15 | 否 |
| 3 重击 | 110ms | 14px | 140 | 0.35 | 否 |
| 4 处决 | **320ms** | 26px | 400 | 0.60 | **是** |

档 1 顿帧为 0 是已验证结论：八颗各冻 35ms 会把"哒哒哒"拆成八次停顿。

### 4.3 数值倍率 ≠ 表现力倍率

- **数值**跨度 6 万倍（线性跟价格，公平性底线，两个标杆都这么做）
- **表现**只有 5 档，相邻约 2~3 倍

观众对"贵了 600 倍"的感知不是"大 600 倍"，而是**"出现了一个我没见过的东西"**。
所以贵礼物买的三样东西里没有一样是"数字更大"：**一段独占的时间**、**压制对方的能力**、
**屏幕上只有他的名字**。

### 4.4 高档礼物的第二维度：压制

在双属性模型里，减益作用于**注入/对冲**，不是作用于手机：

| 表现档 | 附加效果 | 来源 |
|---|---|---|
| 3 重击 | 对方火力**注入** -30%，5 秒（不叠加，刷新时长） | 龙王能力药丸 |
| 4 处决 | 对方火力存量**直接削 50%**，且 8 秒内注入 -50% | 龙王神秘空投 + 螂人杀【处决】 |

档 4 直接削存量，对应螂人杀的【一刀斩/处决】（减敌 3000~100w 兵）——
**这是唯一能瞬间改变差值的手段**，也是"翻盘"的唯一来源。

### 4.5 组刷（留接口，后做）

同一件礼物 10 秒内连送 ≥5 个，触发档位跃迁（档 2 按档 3 演，档 3 按档 4 演）。
不需要新美术，只是把已有演出提前解锁，而"我把它刷出了大招"本身就是爽点。

## 六、落地实测（2026-09-16 已实现并部署）

> ⚠️ 本节是**位置制时期**（手机位置 = 胜负层）的实测记录，模型已于 2026-09-21
> 换成血量制，下表的局长与净差不再成立。保留它是因为三个设计缺陷的结论仍然有效，
> 尤其是第 1 条（护盾不能扣存量）—— 新模型原样沿用。新的实测在 §八。

网页版已按本文实现。`?sim=1&simA=&simB=` 纯数值快进，两秒跑完一局，用来核对局长。

| 场景（每秒注入） | 理论净差 Δinj/LOSS | 实测净差 | 结果 |
|---|---|---|---|
| 0 : 0 | 0 | 0 | **p 永远停在 50.0**，12 分钟判平 ✅ |
| 230 : 230 | 0 | 0 | 双方火力各 **3702**（画面最激烈）而手机纹丝不动 ✅ |
| 110 : 100 | 833 | **833** | 11:38 查岗党胜 |
| 600 : 580 | 1667 | **1657** | 7:14 |
| 23 : 11.5 | 958 | **957** | 10:29（对应"每 10 秒一个爱的爆炸 vs 一半"） |
| 23 : 0 | 1917 | **1900** | 6:39（一方完全不还手） |
| 600 : 80 | 43333 | 受速度上限 | 1:12（上限生效前是 14 秒 —— 那不叫碾压，叫没有过程） |

**压测**（1900 帧、每 300ms 一件礼物、礼物按真实分布八件里一件空投）：
帧均 **1.63ms** / p95 2.20 / 掉帧 0.1%（唯一那帧是第 0 帧预热）/ 顿帧冻结 **19.4%** /
粒子均 304 峰 575 / 弹幕均 **13.5** 峰 29。

### 实现过程中改掉的三个设计缺陷

1. **濒死护盾不能扣火力存量。** 原设计照搬螂人杀"优先掉兵"，写成扣劣势方火力。
   结果是一条正反馈：护盾吃掉劣势方火力 → `min` 变小 → 对冲跟着变弱 → 优势方的火力
   不再被烧掉 → 差值反而越拉越大。实测净差冲到理论值的 **2.4 倍**，越接近终点崩得越快。
   根因是火力同时担着两个职责（护盾的燃料 + 对冲的输入），扣一处动两处。
   **改成按比例减伤，不碰存量**，净差立刻精确落回理论值。
2. **净差没有上限。** 大哥每秒注入 600 而对面只有 80 时，净差能到四万，折合 3.5 个百分点
   每秒，**十四秒**就从中点推到底。加 `MAXDPS = 0.85`（最快一分钟从中点到端点）。
3. **独占窗口开在了错误的时刻。** 原来在礼物发射时就开，可处决要飞一秒半才落地 ——
   等它真砸上的时候窗口早过期了，而飞行途中反倒把常规火力全丢光，画面空成一片。
   改到**命中那一刻**才开（0.8 秒）。修完弹幕在场数从均 1.7 回到均 **13.5**（理论值 13）。

### 新增的诊断参数

| 参数 | 用途 |
|---|---|
| `?sim=1&simA=&simB=&simT=` | 纯数值快进，不渲染。调参不用看画面 |
| `?live=1&liveA=&liveB=&livet=` | 真实对局，快进到指定秒数 |
| `&liveGift=drop&liveAt=&liveSide=` | 在指定时刻送一件礼物（处决只存在零点几秒，不指定截不到） |
| `&liveFreeze=1` / `&liveStop=1` | 冻住进度 / 冻住整个世界 |

## 七、三个待拍板

1. **单局 12 分钟**是按短剧题材推的（已按此实现，`NUM.MATCH = 720`）。螂人杀给主播三档
   可选（45分钟/1小时/2小时）—— 查手机要不要也做成可选（8/12/20）？做成可选则 `DPS`
   必须跟着局长走，否则长局会退化成纯粹比谁钱多。
2. **档 4 处决演出**：现在是**简化实现** —— 1.8 倍体积的重投、半速压过来、命中后 0.8 秒
   独占屏幕，整条被子炸开糊满对方半边屏。要不要换成真正的倾倒式（整盆水泼过去）或
   召唤式（闺蜜团/兄弟团登场，质变最明显，但要新画角色，贵一个量级）？
   换的时候飞行逻辑一行都不用动。
3. **火力要不要做成"局内养成"**（螂人杀的能量电池升级兵种、龙王的仙女棒升级形象）。
   它是留存设计——让观众有理由**在本局内继续刷**而不是刷一次就走。
   查手机可对应：累积火力解锁更狠的物品（发卡→抱枕→被子）。

## 八、2026-09-21：胜负层从"手机位置"换成"血量"

### 8.1 改了什么

需求原话三条：**双方送礼物分别增加各自的拉力值**；**拉力差大于 X 时，每 M 点拉力
每秒扣对方 Z% 的血量，血量归零的一方失败**；**拉力差的值决定对抗线的百分比**。
另：**展示中暂时禁用自动演示**。

| | 旧（位置制） | 新（血量制） |
|---|---|---|
| 胜负看什么 | 手机位置 `p` 到端点 | **血量归零** |
| 手机位置是什么 | 积分量，推过去回不来 | **拉力差的当前读数**，会走回来 |
| 礼物的即时反馈 | 几乎没有（1.5 个百分点／件，要等几十秒） | **1 秒内手机被拽走 10 个百分点** |
| 端点的意义 | 停留 3 秒 = 赢 | 不值钱，只是"此刻力气大" |
| 自动演示 | 默认开 | **默认关**，`?auto=1` 开 |

### 8.2 X / M / Z 的出处（重要，别当成文档抄来的）

查了《螂人杀》的公开文档（`/workspace/A2.txt`、`doc_B.txt`，同一份），里面与本公式
相关的数字只有三组：**兵数表**（点赞 1 → 神秘空投 6 万）、**绝杀线**（兵力差 500w）、
**血量保护**（最后 1000 滴血减缓；最后 100 滴血时兵力 >3000 优先掉兵）。
**它没有"每多少兵每秒扣几个百分点"这一条。** 所以：

- `M = 1000 拉力` —— 本项目 `push = 兵数 ÷ 100`，1000 拉力就是螂人杀的 10 万兵。
  上一版 `DPS` 的分母本来就是它，刻度没动。
- `X = 30 拉力` —— 螂人杀"兵力 >3000 才优先掉兵"里的 3000 兵 ÷ 100。那是文档里
  唯一一个"低于它就不作数"的兵力门槛，拿来当掉血死区最贴。
- `Z = 5 滴/秒/千差` —— **取自需求里给过的例子**（见 §零："一方 1000 另一方 0，
  每秒扣对方 5%"），不是螂人杀文档里的数。

### 8.4 ⚠️ `Z = 5` 与 12 分钟局长不相容

按需求例子取 `Z = 5`，**常规局 1 分 36 秒、碾压局 34 秒就结束**，`NUM.MATCH = 720`
的 12 分钟基本用不上。要回到 12 分钟局长，`Z` 取 **0.27** —— 那正好是上一版 `DPS`
的值，单位完全一致（每千差每秒几个百分点），因为新旧两版本来就是同一个公式，
只是作用对象从"手机位置"换成了"血量"。

两个都能跑，改一个数的事：`?z=0.27` 现场对比。**默认先按需求给的 5**。

注意：**礼物的即时可见性与 Z 无关** —— 那是对抗线那一层给的（拉力差直接映射），
`Z` 只决定"耗多久分胜负"。所以这个选择只关乎局长，不关乎"刷了有没有感觉"。
