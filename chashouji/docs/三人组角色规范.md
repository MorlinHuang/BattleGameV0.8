## 一、每个人必须有的东西（验收底线）

| 段 | 要求 | 样板怎么做的 |
|---|---|---|
| **进场** | 不能是一张图平移进来。要有**姿态变化**：进场里、**人已经露面之后**，至少切一次帧（画外切的不算） | 樱木：腾空扑（dive）→ 砸地（flop，落地压扁）→ 贴地滑（slide）→ 待机。格格：露面时收腿俯冲（tuck）→ 0.6 秒荡到最低点伸腿（kick）→ 抬手蓄力（`改_gege_enter_fine.json`）。B5：四帧走路循环 + 一步一伏 → 站定摆架（idle）。**B5 第二轮打回**：walk1、walk3 是同一条腿在前、双节棍换手，走路帧要重出（6.2 walk 行） |
| **待机** | 呼吸 + 至少一处**次级摆动**（头发、流苏、衣摆、脚、挂件），而且要**在胶片上量得出来**：次级摆动 ≥ 3 px，一次待机里至少完成一口呼吸 | 樱木：背一起一伏（头部峰峰 4.5 px，0.9 次/秒；原来 0.5 次/秒时 ≤ 0.45 px）+ 两只脚懒洋洋翘 + 手里篮球慢慢转；格格：呼吸 + 帽后流苏挂件自己晃（秋千不摆时流苏尖相对挂点峰峰 3.5 px，连同呼吸尖的屏幕位置峰峰 6.8 px）、跟着秋千往后拖 + 秋千本身在摆；B5：站立呼吸（头部峰峰 6.1 px，0.8 次/秒） |
| **出手** | **蓄力 → 出手（东西在这一帧离手）→ 收势 → 回待机**，至少 3 帧（蓄力 / 出手 / 收势） | 樱木：wind 0.28s → throw 0.1s（球离手）→ follow 0.26s；格格：raise 0.12 → wind 0.24 → throw 0.1（绣球离手）→ follow 0.3 |
| **道具** | 手里空着画，道具由运行时画在 hold 点；出完手手里重新"冒"一个 | 樱木的篮球是 3D 转盘图集；格格的绣球是平面图 |
| **锚点漂移** | 逐帧 ≤ 2px（量法见第八节） | 改完重量：樱木 1.37px、格格 1.09px、B5 后脚（不被挡、不截）0.55 / 0.75px（`shots/trio_std/审2_robust合成测试.txt`；报告里的 1.47 是 robust 前脚的噪声上沿，见 8.3） |
| **一致性** | 帧与帧之间人一样大（头的缩放 0.97~1.03）、服装细节一致 | frames.py 残差表最后一列"头"（不是前面搜索那一段的"头缩放"） |

帧与帧之间**硬切**，不做交叉淡化（两张不同姿态叠在一起是两副骨架互相穿透的重影，记忆 chashouji-keyframe-frames 第 8 条）。
硬切不读成卡顿，靠三件事：① 不动的部位严格对齐（下面的配准）；② 换帧落在动作的"节拍点"上（出手那一下、荡到两头停住的那一刻）；
③ 切的那一下配整体的挤压 / 前后甩（引擎做，数据里填幅度）。

## 二、路线：为什么是"动作条帧 + 程序补次级动作"（混合，c）

三条路都试了，证据在 `shots/trio_std/`：

| 路线 | 试的结果 | 结论 |
|---|---|---|
| (b) 切件：把立绘切成大臂小臂转 | `路线对比_切件vs生图.png`：樱木 idle 的小臂绕肘一转，身后露出从没画过的胸口（缺口）；想做"举过头"的蓄力，上臂在原图里根本不存在。记忆 baijia-fx-cutout-rig：被遮住的部位要合成补；查手机 v10~v12 网格变形被用户否掉（"spine 效果还是太差"） | 只能做小幅摆动，做不了蓄力 / 出手这种大姿态 |
| (a) 纯动作条帧 | 同一张图里的 4 个姿势，人的大小基本一致（头缩放 0.96~1.06）；配准后不动部位残差 ≤ 1.71px。**但**模型会把"不动的部位"本身画走样：樱木出手那格腿短了一截，短裤对齐了、鞋还差 20px | 大姿态靠它；必须配准 + 自检 + 移植修补；只靠帧的话待机是死的（一张图） |
| **(c) 混合（采用）** | 关键姿势用动作条帧；呼吸（绕锚点胀缩）、次级摆动（flex 条带错位）、挂件层（parts）、秋千摆、落地压扁、出手前后甩由引擎程序做 | 大动作有画面质量、小动作连续不停；胶片见第八节 |

## 三、流程总览

```
定妆图（美术已在做，buddy/ref/B*.png）
  → ① 动作条生图（第四节提示词，定妆图当参考图，一张图 4 个姿势，绿幕 / 品红幕）
  → ② frames.py cells：切格、出预览，量 head / fixed / anchor 三个框填 frames.json
  → ③ frames.py build：抠像 → 按头统一缩放 → 按不动部位配准 → 图集 web/assets/trio/<编号_名>.webp；看残差和 check
  → ④ 有走样就 graft 移植；看 preview 三张图（frames / onion / yellow）
  → ⑤ 量 hold / 挂绳点 / flex 框（preview/<名>_frames.png 上量，就是 cfg 坐标）
  → ⑥ 在 trio_buddy.js / trio_bestie.js 的 cast 里加这个人（第六节字段）
  → ⑦ 道具：3D 转盘（第七节）或平面图；挂件层用 part.py
  → ⑧ 部署、拍胶片、量漂移（第八节），过自检清单
```

### 目录与命名

- 角色目录：`v14/trio/buddy/<编号>_<拼音或英文名>/`（闺蜜在 `bestie/`），里面 `raw/`（动作条原图）+ `frames.json`。样板在 `tools/samples/` 下，结构一样。
- 图集：`web/assets/trio/<编号>_<名>.webp` + `.json`（frames.py 自动出，名字 = 目录名）
- 挂件：`web/assets/trio/<编号>_<挂件名>.webp`（part.py）
- 3D 道具：`web/assets/trio/prop_<英文名>.webp`（pack_atlas.py）；建模脚本 `tools/3d/<英文名>.py`

  `idle` 待机 / `wind` 蓄力 / `raise` 抬手（蓄力前段）/ `throw` 出手 / `follow` 收势 /
  进场：`dive` 腾空 `flop` 砸地 `slide` 滑行 `roll` 翻滚 `land` 落地 `crawl1/crawl2` 爬 / 秋千：`kick` 伸腿 `tuck` 收腿

## 四、生图：定妆 → 动作条

### 4.1 提示词模板（照抄，替换【】）

**要点**（每一条都是踩出来的）：
- **一张图出 4 个姿势**（地板趴着的人：竖图 `1024x1536` 4 行；坐 / 站 / 挂着的人：竖图 2x2）。同一张图里的人大小、服装最一致；分开生图人会漂。
- **参考图**：定妆图 + 已经出好的同一个人的动作条（第二张动作条带上第一张，最后一格再画一遍 idle 当对齐锚）。
- **写死"不动的部位"**：趴着的写"hips and legs in exactly the same place in every row"，秋千写"board in the same place"。模型不一定听，但能少走样。
- 手里**空着**（EMPTY hands），写"as if holding a ball"让手型对。道具运行时画。
- 引擎画的东西（秋千绳、座板）**不要画**，或者画了用 frames.json 的 `erase` 抠掉（格格就是这样）。绳子写"ROPES ARE NOT DRAWN"。
- 幕布：纯品红 `#FF00FF`；**粉 / 紫 / 红粉系角色用绿幕 `#00FF00`**。生图有时直接回透明底，工具自动识别，别铺回幕布再抠。
- 提示词里**不写作品名、角色名**（借梗不写原名）；**"bikini" + 跪姿 会被拒**，写"crop top and matching briefs"一类描述。
- 朝向：哥们朝左（facing LEFT），闺蜜朝右（facing RIGHT）。
- **定妆时已经拆成几层的人**（B18 扇子、G5 算盘、G13 绳子、G18 翎子和靠旗、G29 竹棒），参考图**只用人那一层 `ref/<编号>_body.png`**，提示词写明 "NO folding fan / NO back flags / NO feathers / NO abacus / NO bamboo staff / NO rope drawn"。这几件东西由挂件层画（6.6 节）；动作条里画了，就会和挂件层叠成两份。

### 4.2 生图自检（出图就看，不行当场重生）

- 4 格里人一样大、衣服细节一样（花纹、扣子、鞋）；不动的部位位置差不多。
- 蓄力和出手的**幅度要大**：缩到游戏尺寸（樱木 ~450px 宽、格格 ~330px 高）还能一眼看出是在"拉"和"甩"。
- 格与格之间留空（工具按连通块切，粘在一起切不开；小的脱开的碎块如流苏会自动并回最近的人）。

### 4.3 后排地面和前排地面（地板）的区别

| 前后倾 | `leanK` 0（趴着） | `leanK` 0：站着的人绕脚底整体一倾，另一只脚就被挪走几 px（B5 量出来 4 px），蓄力、出手的幅度全画在帧上 |

### 6.2 进场 / 离场

`enter` 写成对象 `{ kind, seq, ... }`（旧的单张立绘写字符串）。**通用字段**：

| 字段 | 说明 |

| `enter.seq` | `[[帧, 秒, 'land'?], ...]`：进场里按时间换帧，最后一段写个大数（9）表示一直持续到进场结束。**帧可以写成数组** `[['walk1','walk2','walk3','walk2'], 9]` = 这一段按 `enter.fps` 循环（走路、跑、骑车蹬腿）。标 `'land'` 的那一帧切进来时整个人压扁一下（`enter.sq`，0.12）。**所有 kind 都能写 seq，秋千也能**（格格） |

| **`rope`** | 横绳：一根两头系住的绳，人躺 / 坐在绳上从自己那侧滑进来，在场随绳颠、来回荡 | `ends: [[x, y], [x, y]]` 绳两头（**屏幕像素**，可以在画外）、`touch` 人压在绳上的那一点（贴图像素）、`sag` 坠多少、`sway` 荡几 px、`w / fill / edge`。绳子引擎画、画在人之下 | `测_rope_tether_net`（T7） |

**这 12 种进场，引擎给的路线都是整张图的变换**（平移、转、缩放、淡入），人动不动全靠 `enter.seq` 换姿态。审查第二轮定的硬要求：
- `ride` / `fly` / `drop` / `rope` 的 seq **露面后至少两个姿态**，最后一帧标 `land`。例：ride 蹬地 → 滑行 → 刹车后仰；fly 驾驭 → 跨下来；drop 倒挂 → 翻身伸手；rope 趴绳滑 → 坐起。`测_ride_whip` 格 1~7 全程一帧 walk2 平移进来，就是反例；
- `appear` 淡入 + 由小弹大只是整张图缩放，**淡入结束后必须再换一帧**；
- `rope`、`drop` 在场随绳荡也是整体动，要配挂件（parts：垂下的腿、衣带、铃）带次级动作。

秋千 `swing`：`a0` 进场摆幅、`a` 在场摆幅（rad）、`tau` 收敛快慢、`w` 角频率；`pump: { fwd, back, min }` 在场时往前荡用 fwd 帧、往后荡用 back 帧，摆幅小于 min 不蹬。
**进场的姿态用 enter.seq 写**，别指望 pump：摆幅降到 min 的时刻 = tau × ln((a0 − a) / (min − a))（格格 0.87 秒）比第一次往后荡（π / w = 1.21 秒）早，pump 在进场里只会出 fwd 帧。
格格：`enter: { kind: 'swing', seq: [['tuck', 0.6], ['kick', 9]] }` —— 0.6 秒正好是摆角 A0·cos(wt) 过零（荡到最低点），在节拍点上换帧。

**离场与出手（引擎，修5，2026-09-30）**：离场前装不下一整下出手就不起手。"一整下" = 整段 `atk.seq`（蓄力 → 出手 → 收势）；带 `tether` 的还要加上东西飞到、弹开掉完、线收回手上的时间（B26 = 0.3 + 0.45 × 1.1 + 0.9 ≈ 1.7 秒）；旧的单张立绘出拳 = 伸停回、发波 = 聚光 + 轰。离场前最后这么多秒人在待机（呼吸、flex 次级摆动照跑），读成"打完了、要走"，然后换离场帧。你不用填任何字段，但要知道：**seq 越长，离场前空着的那段越长**（B5 1.4 秒），出手 seq 别拖。
- 为什么不选"进入离场时收掉 clip"：那样出手在任何一格都可能被砍断，蓄力到一半直接换成离场帧（假动作），或者出手帧刚过、收势没放就硬切 —— 恰好违反"蓄力 → 出手 → 收势"完整、硬切不读成卡顿两条；已经飞出去的带线道具也会在离场里被收掉的手拽着。推迟起手只损失离场前最后一下，不会出现半截动作。
- 验收：`v14/trio/tools/exitscan.py` 扫胶片，每格记帧名 + 阶段（`trio.js` 的 `phase()`，胶片格上离场中的角色帧名后标"·离场"），"离场阶段画着出手帧"的格必须是 0（修前组 3 是 61/71，修后 25 人 320 个离场格全 0，`shots/trio_std/修5_离场扫描读数.txt`；对照 `修5_离场_前后对照.png`）。
- 离场途中被叫回（再送一份）：`cd` 按头一次来重新取 0.15~0.4 秒，落地后隔一下才出手，不会一落地就甩。

### 6.3 待机 / 次级动作

|---|---|
| `idle` | `{ frame, breathe: [幅度, 每秒几次, 横向补偿] }`。呼吸 = 绕锚点竖向胀缩（0.014~0.022），横向反着补一点保体积（默认 0.4，**趴着的给 0**，不然贴地的脚左右挪） |
| `flex` | `{ 帧: [[x0, y0, x1, y1, 钉住边, 幅度px, 每秒几次, 跟摆], ...] }`：挂着的东西（流苏、发梢、脚、衣摆）按条带错位晃。钉住边 `'t'` 顶（流苏、头发）/ `'b'` 底（根在下面、往上翘 / 飘的：发髻、翘起来的脚、竖着的翎子）/ `'l'` 左（朝左的人拖在身后的东西、朝右的人往前翘的脚尖：小腿钉住）/ `'r'` 右（**朝右的闺蜜拖在身后（左边）的头发、飘带**，根在右边）。`'b'`、`'r'` 第四轮修订加的，测通胶片 `修4_flex钉底_T15`（G23 发髻）/ `修4_flex钉右_T14`（G22 膝盖），读数 `修4_flex钉右钉底_撕裂读数.txt`。**框除了钉住的那一边，其余三边必须是透明的**，不然错位会把身体撕开。跟摆（秋千）= 摆的角速度 × 这个数，流苏往后拖。只给待着时间长的帧写（idle、秋千的 kick/tuck），出手帧一闪而过不用写。**框量完必须跑 8.4 节的"flex 框三边透明"检查**：格格三个框都压到了肩膀或头发，流苏一甩就把肩膀撕开一个口（`shots/trio_std/审_格格流苏跟摆与肩膀撕口.png`）。**挂着的东西下端或侧边碰到身体的**（流苏贴着肩膀、辫梢压在背上），画不出三边透明的框，不能用 flex，要拆成挂件层（`parts` + `sway`），并在人那一层把它原来的位置补画出来 |
| `parts` | 挂件层（扇子、靠旗、翎子、披风、流苏这类**单独拆出来的一层**）：`[{ src, pivot, z, at: { 帧: [x, y, 角度] }, sway: [幅度 rad, 每秒几次, 跟摆] }]`。pivot 是挂件图上挂住的点（part.py 的 grid 上量）；z −1 画在人后、1 人前；**at 里没写的帧就不画**（出手那帧要把扇子拿下来就不写那一帧）。跟摆 = 秋千 / 荡的角速度（rad/s）× 这个数，挂件往**反方向**拖（rad，不是 px：格格 0.25，秋千最猛时拖 ~0.8 rad）。幅度按"秋千不摆时尖上也 ≥ 3 px"定：幅度 rad × 挂件长 ≥ 3 |
| **拆挂件（lift）** | 帧里已经画着、下端碰到身体的挂件（格格流苏）：frames.json 加 `"lift": [{ "name": "G11_tassel", "from": "idle", "box": { 帧: [x0,y0,x1,y1] }, "hsv": [[[h0,h1],[s0,s1],[v0,v1]], ...] }]`（框是输出像素，每帧框住它、别框进身上同色的地方；hsv 写它的几种颜色，描边自动带上）。build 时从每帧拆出来、原位置补画：**以被挡住那段肩线为界分两侧**（肩线 = 框左右紧挨着的两列里身体从哪一行开始，两点连线），贴身体那侧只从身体往里长（肤色 / 衣服，不透明，肩线上补一道描边），外侧只从外面往里长（背景补透明、帽子 / 头发照旧）。第四轮修订前是四周一起平均，流苏压着肩膀那一截被补成 12×8 的不透明灰块（`修4_G11流苏补画_修前灰块.png`）；改后 `lift_check.py` 在 ±0.12 rad 下补画区灰块 0（`修4_G11流苏补画_肩线补肤色外侧透明.png`）。补过的像素另存 `preview/<name>_holes.png`，挂件图出到 `web/assets/trio/<name>.webp`，并打印 `parts` 那一条（pivot、每帧的 at）直接贴。格格：`tools/samples/G11_gege/frames.json`，放大对比 `shots/trio_std/改_格格流苏挂件与肩膀_x3.png` |
| `ropes` | 秋千（引擎画绳和座板）：`ends` 座板两头、`board` 座板框、`grip: { 帧: [左手点, 右手点] }` 这一帧哪只手握着绳（绳子先拐到手上再往上，手盖住绳 = 握住）、`flowers` 绳上小花颜色、`wood` 座板三色 |

### 6.4 出手

**通用字段**：

| 字段 | 说明 |
|---|---|
| `atk.kind` | 出手写法，见下表 |
| `atk.seq` | `[[帧, 秒, 'fire'?], ...]`：蓄力 → 出手（标 `'fire'`，**东西在这一帧开始的那一刻离手 / 开打**）→ 收势。蓄力总时长 = 提前量：秋千的人会自动在"荡到最前面"那一刻出手。经验值：蓄力 0.25~0.36、出手 0.08~0.1、收势 0.25~0.3；**持续型的（发波、喷、连打、抽打、伸缩拳）出手那一段要盖住它的时长**。出手段的帧也可以写数组 `[['hitA','hitB'], 0.6, 'fire']` = 按 `atk.fps` 来回切（连打） |
| `atk.fps` | seq 里循环帧每秒几帧（B5 连打 10） |
| `atk.hold` | `{ 帧: [x, y] }` 东西拿在哪；**出手帧那一格的点就是出手点**。没写的帧手里不画东西 |
| `atk.from` | 出手点（贴图像素），手里不拿东西的写法用它（连打、抽打、喷；出手帧是循环帧时必须写） |

| `atk.onHit` | 打中之后：`bounce` 弹开 / `heart` 冒爱心 / `lips` 口红印 / `wear` 挂在头上 / **`net` 网兜罩住头**（B17）/ **`freeze` 脸上结冰**（G8）；`miss` 故意扔偏的比例。net、freeze 对所有写法都有效 |

  （`f0 − r − pad`、`f0`、`f0 + r + pad`，pad = 这件东西自己的半径）时，在脸框上沿 − 40 − pad 以上"。前排、上方的人路线不变。

  同一批出手砸在女生脸上的对照读数有几百到两千多，说明探针数得到（`?trioprobe=1`，8.2 节）。

**`freeze` 是半透明冰壳**（第三轮修订）：一块九边的不规则冰壳包住头，外沿蓝线、白色霜边、左上两道高光、下沿四根冰棱。

### 6.5 组表与自由组合

**线上是自由组合**（2026-10-01 用户："点击一次同时出现 3 个角色自由组合，一个从上面，一个在地上，一个趴着的或者从下方出现的"）：每次送礼，后排地面 / 上方 / 前景地板三个槽位各自从本边名单里独立随机抽一人（每边 10 × 10 × 10 种），在场时再送 = 在场的各自续、空出来的槽位随机补人，**每个槽位同时只站一人**（原来的"叠第二组"、备用位 SLOT2 撤了，见文末「自由组合修订」）。**你只要在 `cast` 里加人，他就进了自己那个槽位的抽签池**；还没做的人不参与抽。`groups` 组表线上不用，只给诊断和拍胶片：`?buddy=<组号 1~10>` 按组表召那一组，`?buddy=B5.B13.B23` 直接按三个人召（`?bestie=` 同）。
**因为任意三人都可能同框，站位 `at` 要对本边所有别的槽位的人都成立**：新人上场前跑 `python3 v14/trio/tools/combo_scan.py <buddy|bestie>`，看 `shots/trio_std/组合遮挡矩阵_<边>.txt` 里自己那一行 / 那一列全 0（外扩 4px），末尾「建议站位」给了一套挪法。
后排地面的人：B1~B4 / G1~G3 是 crew.js 的滑板 / 平衡车形象（`ground` 表）；**新做的后排地面角色（B5~B10、G4~G10）也按本规范做成帧序列，加进 `cast`**（`at` 放在自己主角身后的地板上，`depth` 0.8 左右）。
**后排地面的样板是 B5**（`trio_buddy.js` 的 B5，素材 `tools/samples/B5_jkd/`）：模板 C 两张条、`walk` 进场、站姿待机、`rush` 连打。和前排的区别、和 crew.js 的关系见 4.3 节。
B5 的数据由引擎负责人先写进 `trio_buddy.js`，哥们美术接手后照本规范维护。

### 7.1 道具表（60 人逐个判，2026-09-30）

**美术挂数据照这张表抄**：判为做 3D 的，atk 写
`{ kind: 'throw', item: '<道具名>', r, atlas: { src: 'assets/trio/prop_<名>.webp', n: 36, cols: 6, cell, scale }, T, arc, spin: π / T }`
—— r、cell、scale 就是表里那三个数，**r 不能改**（描边宽度是按这个 r 倒推的，画大画小描边就不是 2.8px 了）；
`item` 写道具的真名（`'coin'`、`'pan'`……），**引擎有 atlas 就走图集，不再看 item**（第三轮修订之前 3D 道具只能写 `item: 'bball'`，
牛丸、哑铃、磁带现在可以改回真名）。转速 `spin = π / T`：飞一趟转半圈（skill 坑 6）。

判做不做的标准：**会翻滚、有厚度或有内部结构**的做（翻过去能看到别的面，3D 才比平面图多出东西）；
软的（手绢、纸条、绸子、胸罩）、光效、画在人物帧里的（连打残影、伸缩拳）、**朝向固定直线飞**的（飞镖、飞剑、针筒：
尖朝前不翻滚，3D 转不起来）不做。

| B1~B4 | 水枪 | 不做 | crew.js 画的水柱，喷出去的是水不是一件东西 | — | — | — |

### 7.2 怎么出一件（流程）

样板：篮球 `tools/3d/basketball.py` → `web/assets/trio/prop_basketball.webp`。**先问一句"它在屏幕上多大"**：r 是屏幕半径，描边、渲染边长、达标线全从它来。

```bash
cd /workspace/art/chashouji
timeout 120 scp -q tools/3d/basketball.py tools/3d/common.py kf-deployment:/home/op/bl/
# 快测 8 帧看形体
ssh -n kf-deployment 'cd /home/op/bl && rm -rf out_bb && mkdir -p out_bb && blender -b --python basketball.py -- 8 300 32 /home/op/bl/out_bb/f_ 1'
# 正式 36 帧、采样 128，边长 ≈ 屏幕直径 × 2.4（篮球 r 34 → 160）
ssh -n kf-deployment 'cd /home/op/bl && rm -rf out_bb && mkdir -p out_bb && blender -b --python basketball.py -- 36 160 128 /home/op/bl/out_bb/f_ 1'
scp -q "kf-deployment:/home/op/bl/out_bb/f_*.png" /tmp/bb/
python3 tools/3d/pack_atlas.py /tmp/bb /tmp/probe.webp                 # 先空跑看并集
python3 tools/3d/pack_atlas.py /tmp/bb web/assets/trio/prop_basketball.webp --cell 104 --cols 6   # cell 不大于并集
python3 tools/3d/measure_volume.py --frames /tmp/bb basketball         # 先在 ENGINE 表里加一行 (cell, scale, r, spin, 1)
```
- 建模脚本**只写建模**，最后一句 `render_turntable(名, active=ob, lean=..., screen_r=r)`；风格（灯光、描边、相机）全在 common.py，不改。
- 体积感靠**真几何的内部结构**（每块皮是单独一块厚片、缝是真的缝），材质分区画的线不产生描边、对体积感零贡献。篮球：密度 26%（达标线 20%）。
- 球体的"贴纸残差"天然是 1.0（剪影永远是圆），不用看它，看缝线转起来的遮挡变化。
- 本次踩的坑：删面留下台阶锯齿 → 把缝边顶点投影回等距线；投影把一些面压成细条 → Solidify 的 `use_even_offset` 会在细条上挤出尖刺，关掉；缝宽按"两边描边并成一条线"定（SEAM 0.022），第一版 0.07 在 68px 上是 10px 黑带。

---

- **量**：`python3 tools/3d/prop_check.py <帧目录> <名> <r> <识别色hex> --sheet /tmp/<名>_sheet.png`，一次出五个数 + 一张 1:1 接触表：
  结构密度（≥ 20%）、识别色废帧（≤ 12/36）、**墨块帧**（整帧非描边色不到 15%，≤ 6/36；细长件和背光面见 7.3）、纯黑内腔（≤ 1%）、屏幕外轮廓描边宽（篮球 3.9px）。
  已打成图集的件：`prop_check.py web/assets/trio/prop_<名>.webp <名> <r> <hex> --cell <cell> --scale <scale>`。
- **结构密度会被墨块骗高**：零件间距 g < 2 倍描边时，描边并成一片，密度反而更高。一定跟墨块帧、接触表一起看。
- **立方体要缩**：棱长 2.0 的方块斜着转，对角线 3.46 超出相机画幅 3.3，会被切掉一角。泥土方块用棱长 1.6，r 相应放大。
- **手拼网格**（add_mesh / bmesh）join 完先 `normals_make_consistent`，否则朝里的面 Toon 按背光画成近黑。
- 本轮渲染边长一律 4.8 × r，采样 128；cell = min(并集, 1.4 × 屏幕直径)；超过 120 KB 就降 q（最低 70）。零件多、镂空多的件 alpha 通道占掉大半体积，降 q 压不下去：`pack_atlas.py --aq 70`（alpha 有损，最大误差 9/255，看不出），算盘靠它从 151 KB 压到 116 KB。

1. **有正面的件，姿态按灯定，不是只按"不侧对"定。** sun 从镜头这侧右上方打（common.py，不改），Toon 的面法线离光 ~65° 以外整面落进暗面，
   浅灰壳也发黑。磁带 lean +25 / tilt 0.3 时标签面有 5/12 帧离光 70~83°，整面深褐。
   **转轴往光的水平投影那边偏（lean 取负），起始姿态让正面往上抬（tilt 取负）**：磁带 lean −25 / tilt −0.4 / roll 0.8、项链和算盘 lean −20 / tilt −0.1 / roll 0.2，
   正面离光最多 56~58°，每帧都是亮面。鼠标同理：正面是按键面（+Z），tilt 1.1 让它朝镜头，lean −20。
   算的时候把正面法线按 `Rot(θ, 转轴) · Ry(roll) · Rx(tilt)` 转 36 帧，看它和光方向 (0.27, −0.74, 0.62) 的夹角最大值。
2. **长条件（哑铃、松果）绕贴近自己长轴的斜轴滚**：起始长轴横放，转轴离屏幕横轴 20°、往纵深偏（lean −70）。长轴绕它扫一个小圆锥，
   最多点头 40°，屏幕上永远 ≥ 0.76 倍长；翻滚靠端面、鳞片转过来转过去读出来。
   首版哑铃 lean 60，长轴会转到正对镜头，整只缩成一个圆点（"蘑菇"）；首版松果同理，长宽比 1.5 转出来是圆球。
3. **prim 的 rotation 是物体变换，不是网格。** join 之后网格留在 active 那件的局部坐标里，而转盘会覆盖 rotation_euler：
   哪件当 active，长轴就落在哪根轴上（哑铃第一版起始是竖的）。**join 之前全选 `transform_apply(rotation=True, scale=True)`**，姿态参数才算得准。

另外两条是 skill 坑 4 的具体化：
- **一片片独立的小零件，每片上下两面各出一圈剪影线**：松果 24 片独立鳞在 65px 上 75% 是描边色。改成每圈一整块带厚度、下沿剪成人字齿的"裙子"，
  齿与齿之间不出线，一圈就是一道人字折线（密度 47%）。
- **两块面接平才不出线**：项链银包边比宝石外沿厚一截时，包边内壁是一道剪影线，0.2 单位宽的银边两边各一道描边、只剩 1px 银色。
  让包边内沿跟宝石外沿同高，银边露出来了，外轮廓 8.3 → 3.3 px。

### 8.3 量锚点漂移

```bash
python3 v14/trio/tools/drift.py f.png 12 web/assets/trio/B21_sakura.webp 555x208 4 0 330,150,440,200 712,1330,0.95 300.1,199.2 16 \
```

参数：胶片、格数、图集、格大小、列数、参考帧下标、**量的框**（格内像素）、at、anchor、搜索半径、id / names（按 f.json 每格取那一帧当模板）。
量法：取图集里那一帧"不动部位"那块 + alpha 当遮罩模板，到引擎按 at/anchor 算出的位置 ±R 里找（只比人身上的像素，背景滚、东西飞过都不影响）。
- **框选紧贴锚点的那一截**（樱木贴地的肚皮到大腿 `330,150,440,200`、格格压在座板上的臀底 `60,188,130,214`）：呼吸绕锚点胀缩，框离锚点越远读数里呼吸越多。
- 框里不能有会被别的东西盖住的地方（格格膝上重新冒出来的绣球连流苏会盖到臀侧，框第一版到 x 150 就被骗出 13px）；残差比别的格大一个数量级 = 被挡了，看图确认。
- 秋千的人加 `trioswing=0` 拍；不加的话要给 `pivot= rot=`，但一小块离转轴 700 多像素时转一点和平移一点分不开，dx 不可信。
- 进场帧（在动）、`（不在场）` 的格不算。
- **后排地面的人**：不动的脚常被主角的腿挡住一块（B5 前脚被男生小腿挡住，不截残差 0.45、读数被拐走 4 px）。加 `robust=0.08`：每个像素的平方差截在 0.08，被挡的那几块只算一个上限：
  `python3 v14/trio/tools/drift.py 改_B5_atk.jpg 12 web/assets/trio/B5_jkd.webp 423x482 4 0 130,440,215,480 800,1158,0.85 260.7,478.1 16 id=B5 names=idle,wind,hitA,hitB,walk1,walk2,walk3,taunt robust=0.08`
- **robust 的用法（审查第二轮，合成测试见 `shots/trio_std/审2_robust合成测试.*`）**：
  - 它不会放过 ≥ 1 px 的真漂移：注入 0.5~6 px 都能量回，误差 ≤ 0.4 px，而且偏小；
  - 但脚被挡住时，截断后的误差面有两个谷，读数会在两个谷之间跳，每格 ±1 px（B5 前脚 idle 格 8→9 跳 2.07 px，同两格后脚只动 0.99 px）。

  所以后排的人：
  - **主读数用没被挡的那只脚、不截**（B5 后脚框 `330,420,405,462`：idle 0.55、atk 0.75）；
  - 两只脚都被挡才用 robust，门槛收到 **≤ 1.6 px**；1.6~2.4 之间的看 onion 图人工判；
  - 前后两格跳超过 1.5 px 的，那一格的读数作废。

## 修9：标了 ammo 的挂件（2026-10-01，引擎负责人）

起因：闺蜜 8299ae8 的 G10 肩上球棒是挂件（`ammo: true`）。扔出去以后，飞出去的那根还在弹开往下掉，肩上又冒出一根，同时出现 0.1~0.3 秒（`shots/trio_bestie/R_g10_hit` 格 10~12，那时已回到 idle 帧）。

1. **`b.ammo` 的语义 = 此刻手里有没有这件东西**：
   - 出手帧 `fire()` 那一格变 false；
   - 出手动作（整段 seq）收完、扔出去的那件也回来了（`reload()`），才变回 true，从小长大（`TRIO.pop` 0.16 秒）；
   - 手里没有就不起手；`drawHeld`（hold）和标了 ammo 的挂件（`drawParts`）都只在 true 时画。
   原来的 `reload()` 只等带线的东西收回（`onLine`），对篮球、绣球这类"扔一个手里再冒一个"的道具是对的。但挂件本身就是扔出去的那一件时，它在飞、弹开、往下掉的整段都不在手上。美术建议在 drawParts 里加一行判 `b.ammo`，这不够：动作收完那一刻 ammo 就已经回到 true，而球棒还在掉。
2. **引擎写法**：挂件里有 `ammo: true` 的人（`ONE`，这件东西只有一件），`reload()` 要等飞出去的那件从画面上消失（`away()`）才回手。回手后至少拿稳 `TRIO.pop + 0.25` 秒才起下一手：它回来时冷却早就走完了，不留这一拍会回手即扔，肩上那根只闪一格。没标 ammo 的人，行为和节奏都不变。
3. **cfg 写法**：挂件就是甩出去的那一件（同一个造型）时，写 `ammo: true`。
