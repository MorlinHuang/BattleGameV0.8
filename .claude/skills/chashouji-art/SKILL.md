# 《查手机》美术素材

> **2026-09-24 起角色改走 v14「动作片段」**：僵持循环 + 落后方被拉倒三档（跪 / 扑倒 / 趴）两边各一套，贴图由
> `chashouji/v14/build.py` 抠像、统一缩放 0.66、对齐、自动找手机点。生图规矩不变：
> 以 `v14/pose/00_僵持.png` 为参考图做 image-to-image，**手机一律横拿、屏幕朝镜头、
> 女左端男右端**（这条写进每一张的 prompt，11 张全部守住了）。下面讲的"每 1% 一张"
> 那套是 v13，已退役，抠像与尺度的经验仍然适用。
>
> **朝向铁律（用户 2026-09-24 定，任何姿势都适用）**：女生永远面朝右、男生永远面朝左，
> 胸、胯、膝、脚尖都朝对方。① **往后拉 = 倒退着走**，绝不转身背对对方"走开"（第一版
> 拽着走就是胯转过去了，用户原话"动作会非常丑"）；② **被拉倒 = 头和胸朝对方、腿在身后**，
> 按"跪 → 一条腿跪一条腿往后滑地往前扑 → 趴在地上"三档往下掉。**不要坐姿**：坐着腿拖在身后
> 读成"身体扭了 180 度"，坐着腿伸向对方用户也说"不好"。prompt 里写大写 IMPORTANT，
> 并点名"头朝谁、腿在哪边"。现行 `pose/21~26` 是用户选定的六张（趴那档以旧 02 男趴地为
> 参考图，用户点名认可）；01~04 拽着走/坐地已不用。
> **背景补画（镜头拉远 2/3 时）**：`v14/bg/ext/` 里是画布/蒙版/生成图。整间房 + 上下要补的部分一起缩进 1536×1024，
> 蒙版只放开上下和右侧空白，一次出图；再放大贴回、原图像素原样。三个坑：补的顶角线三间房高度不同（按行重映射对齐到客厅的 76 行）；
> 门洞上方多画出一截悬空门楣（用上方纯墙盖掉）；补画墙比原图略暗（逐列差值往上 220 行渐隐补平）。两间房墙色交界处加了竖向墙角线。
> 趴地那两张手机是斜着拿的 —— build.py 找手机按块自身主方向量长宽，不能改回水平外框。
>
> **步态（2026-09-25 起，`v14/gait/<姿势>/`）**：用户要"倒退时双腿交替向后"。
> ✗ 第一版把补帧挂在"狼狈度"上逐张播（`tween/`，已删）：狼狈度涨得慢，标准对局约 3 秒才换
> 一张，其余时间同一张图在平移，用户原话"非常机械的平移"。而且整张重画，上半身每张都抖。
> ✓ 现在：每档一个**八格步态循环**（`gait/<档>/`：base = 该档关键帧当第 0 格 + f1~f7）：
> 0 双脚着地 → 1 前脚跟离地 → 2 抬起的脚从站地那条腿旁穿过 → 3 往身后伸、快落地 → 4 换腿双脚着地 → 5~7 同 1~3 换腿。
> 规律是**站地的脚从身后一路挪到身前、抬起的脚从身前摆到身后，每格只挪一点**。第一版四格（站定/抬腿/换腿/抬腿）
> 每格脚都跳一大截，用户原话"后腿非常不连贯"。每个相位 n=2 生两张，一张给前半圈、一张给后半圈（换腿）。
> 用 **蒙版局部重绘只重画赢的那一方的腿**（`mask.png` 透明区 = 胯以下那一块，要避开输的那方），其余像素原样，锚点沿用 base。
> prompt 模板在 `v14/gait/PROMPTS.md`（LIFT-OFF / PASSING / REACH 三句）。三条实测：
> ① prompt 开头写 **"Keep the ENTIRE image exactly as the reference, including the flat solid MAGENTA
>   background"**：只写"Inpaint ONLY the masked area … never black"时黑底+光晕 4/4；改后大多是品红底，
>   但男生扑倒那档仍有七成黑底 —— 每相位多生几张再挑。
> ② 重画的腿普遍**短一截**（脚离原地面线 20~55 原图像素）。build.py 的 `plant_feet` 把蒙版那块竖着
>   拉/压到最低那只脚落回原地面线；不能整张下移 —— 趴着的输家会陷进地板。
> ③ 各档生图时人被画小了 5~9%（只看扑倒/趴），`head_scale` 按赢方的头补回来。
> 还没做：僵持档（n）挪动时的步态 —— 现在还是时间循环加平移。

角色是 **0~100 每 1% 一张预渲染关键帧**，现有 89 档（29 档生图画的，其余光流插出来），
成品在 `web/assets/frames/`，960×900 PNG。

**这条路是选定的，不要回头去做骨骼动画。** 两个人抢同一部手机，肩肘腕的相对关系
每一档都不一样，一套骨骼去凑永远在"手够不到机身"和"肘折过头"之间取舍。
v10~v12 的网格变形 + 半骨骼已被用户否掉（原话："spine 效果还是太差了"）。

**接受的代价**：手机屏幕内容烧死在帧里（没法动态显示聊天记录，所以才有外挂气泡）；
劣势方压暗做不了（两人在同一张图上）。

## 开工前必须问清

1. **要生的是角色帧还是小物件？** 两者构图规则完全不同——角色帧要品红幕布 +
   两人同框 + 参考图锁形象；物件要平铺、无重叠、无投影。
2. **是补一张还是重做一段？** 补单张优先找**单点离群**（与左右邻居差异都 >80%
   的那一张），重画它的收益比补二十张还大。
3. **新帧要插进现有 89 档的哪个位置？** 相邻档差异 >42% 的区间不能用光流插，
   只能生图。

## 一、生图

`generate_image` **不产透明底**（传参也没用），所以角色一律画在品红幕布上。
提示词末尾强制写：

> 背景必须是纯正的品红色 #FF00FF 单色平涂，无渐变、无阴影、无地面、无投影、
> 不要在角色下方画任何影子。

**风格锁定**（缺一组就出 3D）：

```
正向：纯2D扁平卡通 / 粗黑描边 / 大色块平涂 / 赛璐璐 / 成年人形象
禁止：3D渲染 / 建模质感 / 塑料光泽 / 皮克斯 / C4D
     细碎纹理 / 花纹图案 / 噪点 / 杂物堆 / 密集小物件
     透明背景 / 棋盘格背景 / 少女感 / 二次元萌系
```

"细碎纹理"这组是用返工换来的：有一批做成"居家客厅狼藉 + 花纹地毯 + 满地零食"，
画面好看但碎到无法拆件，整批作废。

**画幅**：目标 960×1334。工具没有这个尺寸，按内容选换算法——

| 情况 | 做法 |
|---|---|
| 底部只有装饰小字条 | 1024×1536 → 裁底 113px → 缩到 960×1334（横竖同为 0.9375，无形变） |
| 上下都被 HUD 占满 | 1024×1536 → 等比缩到 889×1334 → 两侧各镜像扩边 35/36px |
| 中间构图 | 1024×1536 → 960×1440 → 上下各裁 53px |

**不要直接 resize**（横向拉伸 8%）。生图偶尔不按请求尺寸返回（实测有 941×1672），
脚本必须按**实际尺寸**算。**顶部 HUD 必须保，裁底不裁顶。**

角色一致性靠 **image-to-image**：拿定稿图当参考图，相邻帧互相当参考图。
细节与已定稿的构图结论见 `references/genimage.md`。

## 二、品红抠像

判据：**品红度 `m = min(R,B) - G`**，m 大 → 背景。纯品红幕布上这个差值接近 255，
而角色身上任何颜色都到不了——浅粉睡衣只有二十几（高明度低饱和，G 也高），
红发夹是纯红正好是 0。单条软阈值就够。

四个必踩的坑：

1. **uint8 直接相减会下溢**，必须先 `astype(np.int16)`。
2. **色溢抑制只能作用于 `alpha < 1` 的过渡带**。写成 `(m > 12) & (alpha > 0)`
   会波及全部不透明像素——**粉色的 R、B 天然高于 G**，睡衣阴影 `(230,175,195)`
   算出 `m=20`，被压成灰紫 `(182,175,182)`，整件粉睡衣褪成灰底。
   色溢在物理上只是幕布反射到边缘，压制内部像素本身就是错的。
3. **不要加 `binary_fill_holes`**——它会把两人躯干与手臂围出来的幕布三角当成洞
   填实，黄底自检上是两人中间糊着一大块品红。
4. **缩放/喂 GPU 之前必须做边缘颜色扩散（edge extend）**。抠像只改 alpha，
   透明区 RGB 仍是整片品红，LANCZOS 和 GPU 双线性采样会把它混进边缘出紫边。
   贴纯色底上目视看不出（alpha=0 处本来不显示），只在采样跨边界时暴露。
   实测全透像素中品红占比 99.6% → 0.1%。

**自检：把抠好的图贴到亮黄底上看整张。** 单点采样会漏——采到 `m=7~11` 的点
不触发 spill，数据"正常"但图是坏的。

脚本：`v13/cutout.py`（抠像）、`web/prep_assets.py`（含 edge extend）。

## 三、关键帧的三条命门

1. **尺度基准是女方浅粉睡衣的面积开方**，不是整组面积、不是外框高度。
   粉色是她独有的（白兔图案和红滚边都落在判据外），她在 p=15 以后始终是站立
   前倾的同一个人，实测 p=20~70 稳定在 325~344（±3%）。
   外框高度不行——男方倒下那几档只有 760 高，按它归一化会把整组人放大 45%、
   宽度撑到 1104 溢出画布。
2. **水平按 alpha 质心对齐，不按外框中心。** 外框边缘是甩出去的头发和伸直的手脚。
3. **相邻帧硬切，不做交叉淡化。** 两张画的是不同姿态而非同一姿态的不同时刻，
   叠在一起是两副骨架互相穿透的重影。（用户原话："不要用模糊，直接硬切"。）

完整管线（归一化、区间传播、补帧策略、画幅切断与 inpainting）见
`references/keyframes.md`。脚本：`v13/cutout.py` `export_frames.py`
`interp_frames.py` `compose.py` `pick.py`。

## 四、纹理尺寸（差 6 倍）

**GPU 块压缩（DXT/BC）要求边长是 4 的倍数。** 画布高 1334 不是，引擎只能退回
未压缩的 RGBA——93 张就是 **454MB**。裁成只覆盖人物的 **960×900** 横带之后是
**77MB**。引擎侧按 `FRAME_TOP = 308` 把横带贴回 960×1334 画布。

## 五、物品与粒子素材：Blender 转盘序列帧（已完成）

八件飞行物和命中特效的实体粒子**不走生图**，走离线 3D 渲 2D 序列帧。
美术硬约束仍然是 2D 赛璐璐 —— 3D 只是个画帧的工具，出来的必须看不出是 3D。

**整条管线、五把量尺、九个坑都收在 `danmu-3d-sprite` 那份 skill 里**，
要出新物品、改形体、调描边、查"为什么没有体积感"一律先读它。这里只留
两条跟生图那边交界的事：

- 3D 素材的配色**不能照抄矢量版**。同一个十六进制在这套灯光下会整体亮一档，
  浅色尤其：抱枕 `#fdf2f6` 渲成 (222,220,221) 中性灰，粉味被洗光，得压到 `#f6cfe0`；
  奶茶杯 `#e8c9a0` 要加暖到 `#efb877`；手柄摇杆 `#8fe3ff` 渲出来是灰蓝，压到 `#5cc9f2`。
  规律是**浅色压一档、暖色再加暖一点**，定稿前按真实绘制尺寸贴到米色底上看。
- 描边色这边是暖黑 `#3a2c26`（跟角色线稿同一个），但**要运行时染色的粒子贴图**
  必须渲 55% 中性灰 `8c7d74` —— `multiply` 会把描边一起乘，白羽毛乘白还是深棕，
  在近白的羽毛上重得像瓜子壳。渲中灰之后描边自动等于"主色 × 0.55"。
  （`multiply` 还会把透明区的 alpha 抬成 1，引擎侧必须再 `destination-in` 切回轮廓。）

### 仍然是几何剪影的那一块

`SILH`（残影用的外轮廓）**不换贴图**。残影只需要形状，而且贴图剪影带细节，
四个叠起来会糊成一团 —— 贴图版残影改成两个、浓度减半。
