# 弹幕飞行物的 3D 转盘序列帧

做的是这样一件东西：物品在 Blender 里程序化建模 → 绕一根斜轴转一圈渲 36 帧 →
裁成正方形格子打成一张 WebP 图集 → 引擎按当前朝向取对应那一格 `drawImage`。
观众看到的是一个有体积感的东西边飞边翻，而引擎只做了一次贴图绘制。

**这不违反"美术必须 2D"**：3D 只存在于离线渲染，交付物是平面序列帧，
风格由 Toon BSDF 硬边二分 + Freestyle 描边控制，出来就是赛璐璐。

参考实现在 `art/chashouji/tools/3d/`，八件礼物 + 七种粒子都是这么出的。

## 文件分工

| 文件 | 管什么 | 谁能改 |
|---|---|---|
| `common.py` | 灯光/相机/材质/描边/转盘，**全套风格** | 只有管线负责人改。改一处等于改全部素材 |
| `<物品>.py` | **只写建模**，最后一句调 `render_turntable` | 做这件物品的人 |
| `pack_atlas.py` | 并集裁切 → 下采样 → 打包 → 算出引擎要填的 `scale` | 不常改 |
| `measure_volume.py` | 量"这东西到底在不在三维里转"，五把尺子 | 加尺子时改 |
| `probe_ink.py` | 描边宽度标定探针（渲正方块量墨边） | 怀疑线宽不对时跑 |

物品脚本长这样，风格全从 `common` 来：

```python
import sys, os
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from common import *

init()
mat('body', '#e63a62')
ob = prim('cube', 'body', size=2.0)
...
render_turntable('ringbox', active=ob, lean=40, tilt=0.26, roll=0.20, screen_r=64)
```

## 流程八步

1. **建模**，主体直径做成 `NOMINAL=2.0` 个 Blender 单位（`pack_atlas` 靠它反算 `scale`）
2. **选转轴** `lean`（下面「转轴」一节）
3. **快测 8~12 帧**，看形体和转法对不对，这一步渲得快、改得起
4. **量一轮并集占比**，按 `res = 单格 / 并集占比` 反推正式渲染边长
5. **正式渲 36 帧**，采样 128，`screen_r` 传引擎里的半径
6. **打包**：先空跑一次拿并集，再定 `cell`（**cell 绝不能大于并集**，那是在放大像素）
7. **填引擎**：照 `pack_atlas.py` 打印的那行填 `cell` 和 `scale`，每次重渲都要重填
8. **量 + 看**：`measure_volume.py` 过一遍，再按**真实屏幕尺寸 1:1** 贴出接触表逐帧看

## 判断做得好不好：两把尺子一起看

### 尺子一：内部结构密度 ← 这是主尺

把外轮廓那一圈剥掉，看剪影**里面**还剩多少描边。转动时眼睛真正读到的立体信号，
是内部结构的遮挡关系在变——哪片花瓣压住哪片、盖子转过去挡住了戒指。外轮廓变化
只说明"形状变了"，撑不起体积。

实测（《查手机》八件）：花束 46%、奶茶 25%、相框 24%、戒指盒 17%、手柄 14%、
抱枕 4%、发卡/瓜子 0~1%。再乘屏幕面积得到**屏幕上的结构量**：花束 199、手柄 17、
抱枕 7、发卡瓜子 0 —— 花束是手柄的 12 倍、抱枕的 28 倍。

用户说"没有体积感"时，先量这个。**转轴和转速都调不动它**。

达标线：密度 ≥20%（小件）/ ≥25%（中件），屏幕结构量 ≥10（齐射档）/ ≥60（单投档）。

### 尺子二：识别色 ← 没有它会被骗

**结构密度这把尺子会被黑块骗：越糊分越高。**
发卡两个方案横着比，蝴蝶结密度 70% 高过鸭嘴夹 57%，但同尺寸下蝴蝶结的可见粉色
只有鸭嘴夹一半 —— 62px 上就是一坨深色里透出几根粉丝。

所以必须配一把识别色的尺子：取这件东西最有辨识度的那个颜色（奶茶的粉吸管 /
戒指的金环 / 发夹的粉），逐帧数像素，**低于中位数 12% 算废帧**，废帧不超过 1/3。

### 辅助的三把（`measure_volume.py` 里都有）

- **贴纸残差**：把第 k 帧在画面内旋转缩放去套第 0 帧，取最好那次的 IoU。
  2D 图打转的话随便哪帧都能转回去，IoU 接近 1。0.9 以上基本是贴纸
- **面积变化率 / 细长比波动**：都是旋转不变量，平面内打转不会改变它们
- **每帧跳变**：按引擎实际转速换算到相邻两渲染帧之间，跳太大读成"闪"不是"转"

## 坑

### 1. 线宽有两个入口，而且是相乘的 ★踩过两次

`render.line_thickness`（全局）和 `linestyle.thickness`（每档自己的），
ABSOLUTE 模式下**相乘**。`probe_ink.py` 渲正方块标定出来：

    线宽 ≈ 0.85 × render.line_thickness × linestyle.thickness − 0.65

证据是对称性：2.6×5.2 和 5.2×2.6 渲出来都是 10.94px，一模一样。

**把同一个倍率乘进两处，线宽就按平方涨。** 这个坑咬过两次：
超采样 `ss`（1/2/3 渲出 4/14/30px，发卡整根被描边吞成一条墨胶囊）；
按屏幕倒推的倍率 `k`（戒指盒 k=1.97，描边到屏幕上是 **11px**，整件糊成黑块）。

**根治**：`render.line_thickness` 固定 1.0 当中性基准，所有倍率只乘进 linestyle 一边。

顺带：**超采样这条路直接别走**，Cycles 每像素 128 采样抗锯齿就够了。

### 2. 两档描边里有一档是空的 ★很难自己发现

想让外轮廓粗、内部结构线细，很自然会写成
`select_silhouette` 一档 + `select_border` 一档。
**但 border 指的是网格的开放边，而这类物品都是封闭网格，那一档一条线都不产生。**
所谓"两档"一直只有一档在画——于是调内部线宽完全没反应（1.1/0.7/0.45 三档渲出来
黑占都是 77%），会把人往"内部线太粗"的方向带一整轮。

`select_external_contour` 也救不了，正交相机下同样不出线（探针里零个描边像素）。

**结论**：外轮廓和自遮挡线在这套用法下**分不开**，只留一档 `select_silhouette`，
把宽度定准就是了。

### 3. 描边宽度必须一路算到观众屏幕上

素材要缩两道：`渲染边长 R →(并集裁切 side)→ 图集 cell →(引擎绘制)→ 屏幕 px`。
并起来 `屏幕描边 = 渲染描边 × px/side` —— **cell 正好约掉**，所以调单格边长根本
改变不了屏幕描边，"最终像素"那种只管到图集的口径是假的。

传 `screen_r`（引擎里的半径），框架按屏幕目标倒推：

    渲染描边 = OUTLINE_W × R × (NOMINAL/ORTHO) / (2 × screen_r)

scale 在推导里约掉了，所以这个数开渲前就能算准。目标值 **2.8 屏幕像素**
（实测 2.4~4.1 都能看，低于 2 在明亮底图上开始糊进背景）。

### 4. 排得下几个零件是一道能算的题

一个零件在屏幕上只有 10px，而它上下各有一条 2.8px 的描边——填色区只剩 4px，
再一抗锯齿就整个变成墨色。发卡的蝴蝶结方案、五颗细瓜子、齿距 0.42 都是这么死的。

**算式**：屏幕描边宽 W（实测值，不是标称值）、零件间距 g，
**`g < 2W` 两条描边就连成一条粗黑带**。手柄正面横向只有 96 屏幕px、竖向 34px，
W≈8px（当时还带着平方 bug）→ 一排最多四个零件，且分不出上下两层。
按这个算式砍掉的：ABXY 四个分离小凸起、十字键和 ABXY 各自的浅色底盘（边距 1.4px）。

**堆结构和堆零件数不是一回事**：零件多但每个都被描边吃光，只会得到一块黑。
瓜子从五颗细的改成四颗胖的（单颗 0.74 宽 ≈ 屏幕 17px）才立住。

**色点别做太小**：手柄 ABXY 第一版色点半径屏幕 4.2px，渲出来红色像素中位只有
13 个、还有两帧是 0，识别色废帧判据当场挂掉。

### 4b. 材质分区不产生描边——在密度这把尺子下等于不存在

用材质分区画缝线、兔耳、脊线、色块，好处是**不占间隙预算**（不产生描边，
所以不受 `g ≥ 2W` 约束），坏处是**对体积感零贡献**：密度尺子量的就是描边像素。

所以分工是清楚的：**分区只管"认得出"，真几何才管"有体积感"**。
补结构只有真几何一条路；放不下真几何时退回分区，那是保可读性，不是保体积感。

配套三条几何做法（都是踩出来的）：

- **贴在面上的凸块要带直裙边扎进主体**，别贴着放——两个面在接触圈附近几乎相切，
  Freestyle 会长出一圈乱跳的小黑睫毛。
- **顶面要比底面外扩一点点（悬挑）。** 垂直壁在正视时法向正好垂直于视线，
  前后朝向符号不定，描边会一帧有一帧无地闪。
- **顶面按同心环细分，不要从中心拉扇形。** 扇形三角又长又尖、面心落不准，
  想在凸块顶面用材质分区画小色点根本画不出来。

### 5. 转轴是一根连续参数，不是 X/Y/Z 三选一

`lean` = 转轴从视线轴往屏幕横轴偏多少度：
**0 = 绕视线轴 = 纯屏幕内旋转 = 2D 贴纸打转**（36 帧只是同一姿态的 36 个副本，3D 白渲）；
**90 = 绕横轴翻跟头**，体积感最足但有正面的物件翻过去就是背面。

正面朝向在转过 180° 时偏转 `2*lean`，这就是选档依据。实测档位：
各向同性的（花束）随便，90 最好看；回转体（奶茶）68；有正面的（戒指盒/相框）40；
两面都有内容的扁平件（抱枕）**直接给 90**，反直觉但实测废帧最少；
细长件看长轴跟转轴的屏幕投影夹角——长轴竖着（发卡/瓜子）给 50 没问题，
长轴横着（手柄）只能给 35，**救法不是压 lean 而是加 roll 把物体在画面内斜过来**。

**可读性判据不要推到 36/36**，那会把立体感全换掉，2/3 够了。

### 6. 转速按"飞行途中转半圈"，不是转一圈

半圈就把可见面完整换过一遍了，体积感全在里头。转一圈的话每帧要转 14°，
而转盘每格才 10°——**每帧跳 1.4 格已进走马灯区**，眼睛读不出"一个刚体在转"，
只读到一连串跳变的形状，也就是"闪"。

`spin = π / 飞行时长`。每帧转 5~8°（半格到 0.8 格）姿态才是连着的。
另外总共只转半圈时**起始相位决定一切**，不要满圈随机，从第 0 格（建模时的正面）
起步、抖 ±10° 就够。

### 7. 封闭内腔会渲出纯黑

场上只有一盏 sun + 环境光，光进不去夹缝。相框背后用薄板做支脚时，板与框背之间
的口袋最高 14% 的像素是纯黑——这套画风里最深的颜色是描边，突然一块纯黑读成
"破了个洞"。**改成实心楔块**（没有内腔）根治。验收前扫一遍 alpha>200 里亮度 <12 的占比。

同理：两个面几乎相切处 Freestyle 会长出一圈乱跳的小黑睫毛（圆柱+同半径球帽、
球压在平面上），改成一块整的旋转体网格就干净了。

### 8. 体积卡点是编码，不是尺寸也不是帧数

同样 36 帧 268px：PNG 2433KB、WebP 无损 1625KB、**WebP q=88 只有 408KB**。
alpha 通道始终单独无损，RGB 平均差 4.3/255，2 倍放大肉眼看不出。
降边长或砍帧数是拿画质换体积，换编码不牺牲任何东西。

### 9. cell 跟着并集走，绝不上采样

`--cell` 大于并集就是在放大像素。**换 lean 档、改描边宽度都会改并集**
（斜轴扫的圆更大、描边外扩），每次重渲都要重量一遍再定 cell。

## 参数速查（《查手机》实测值，换项目要重定灯光）

```python
ORTHO      = 3.3       # 正交宽度。主体 2.0 单位 → 占画幅 60.6%
NOMINAL    = 2.0       # 主体标称直径
INK        = '3a2c26'  # 描边色，取角色线稿那个暖黑
OUTLINE_W  = 2.8       # 描边，**屏幕像素**
# 灯光：SUN angle=0.02 energy=2.6 rot=(52°,0,20°)
# 环境：(0.86,0.88,0.92) strength 1.25 —— 默认那个近黑的环境色会让 toon 暗面死黑
# 相机：ORTHO，location=(0,-6,0)，rot=(90°,0,0)
# 渲染：CYCLES CPU，samples 128，film_transparent，PNG RGBA，关 denoising
```

要运行时染色的贴图（粒子那种）另一套：描边渲 55% 中性灰 `8c7d74`，
引擎用 `multiply` 染色后必须再 `destination-in` 切回轮廓——`multiply` 会把透明区
的 alpha 抬成 1。

## 开工前必须问清

1. **这件东西在引擎里的半径 `r` 是多少**——描边宽度、渲染边长、达标线全从它来
2. **它在屏幕上有多大**（`2r×scale`）——46px 和 206px 是两种做法，前者别指望单件有体积感，
   齐射档的看点是"一群扑过来"
3. **底图是亮是暗**——这套描边参数是被明亮客厅底图逼出来的，换底图要重定
4. **有没有正面**——决定 `lean` 往大给还是往小给
